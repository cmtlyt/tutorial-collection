# Zero-shot / Few-shot Learning

> **版本**：v1.0  
> **最后更新**：2026-04-14

## 📖 概述

Zero-shot 和 Few-shot Learning 是 Prompt Engineering 中最基础也是最重要的技术。它们通过提供不同数量的示例来引导模型完成任务，无需额外的训练。

## 🎯 核心概念

### Zero-shot Learning

**定义**：在不提供任何示例的情况下，直接让模型完成任务。

**原理**：利用模型在大规模预训练中学到的知识和模式，通过清晰的指令直接生成结果。

**适用场景**：
- 简单明确的任务
- 模型已经熟悉的任务类型
- 不需要特定格式的输出

### Few-shot Learning

**定义**：提供少量示例（通常 1-10 个），引导模型理解任务模式。

**原理**：通过示例展示输入-输出的对应关系，帮助模型快速学习任务模式。

**适用场景**：
- 需要特定格式或风格的任务
- 复杂或新颖的任务
- 需要控制输出质量的场景

## 💡 Zero-shot 实践

### 基础示例

**情感分析**

```python
# Zero-shot 提示
prompt = """
判断以下句子的情感倾向（积极/消极/中性）：
这家餐厅的服务非常好，食物也很美味。
"""

# 输出：积极
```

**文本分类**

```python
# Zero-shot 提示
prompt = """
将以下新闻归类为以下类别之一：体育、科技、娱乐、政治
新闻内容：苹果公司发布了新款 iPhone，采用了最新的处理器技术
"""

# 输出：科技
```

**问答**

```python
# Zero-shot 提示
prompt = """
回答以下问题：
问题：法国的首都是哪里？
"""

# 输出：法国的首都是巴黎。
```

### Zero-shot 优势

✅ **简单直接**
- 无需准备示例
- 提示词简洁
- 快速实现

✅ **节省 Token**
- 减少输入长度
- 降低成本
- 提高效率

✅ **灵活性高**
- 适应各种任务
- 易于调整
- 快速迭代

### Zero-shot 局限性

❌ **准确度不稳定**
- 依赖模型理解
- 可能产生误解
- 输出质量波动大

❌ **格式控制弱**
- 难以控制输出格式
- 可能不符合预期
- 需要后处理

❌ **不适用复杂任务**
- 复杂推理困难
- 多步骤任务效果差
- 需要更多指导

## 🎯 Few-shot 实践

### 基础示例

**情感分析**

```python
# Few-shot 提示
prompt = """
判断句子的情感倾向（积极/消极/中性）：

示例 1：
输入：这家餐厅的服务非常好，食物也很美味。
输出：积极

示例 2：
输入：这个产品质量太差了，用两天就坏了。
输出：消极

示例 3：
输入：今天的天气还不错。
输出：中性

现在请判断：
输入：这部电影真的太精彩了，我强烈推荐！
输出：
"""

# 输出：积极
```

**文本分类**

```python
# Few-shot 提示
prompt = """
将新闻归类为：体育、科技、娱乐、政治

示例 1：
输入：中国队在奥运会上获得了金牌
输出：体育

示例 2：
输入：谷歌发布了新的 AI 模型
输出：科技

示例 3：
输入：某明星宣布结婚
输出：娱乐

现在请分类：
输入：政府发布了新的环保政策
输出：
"""

# 输出：政治
```

**代码生成**

```python
# Few-shot 提示
prompt = """
根据描述生成 Python 函数：

示例 1：
描述：计算两个数的和
代码：
def add(a, b):
    return a + b

示例 2：
描述：计算列表的平均值
代码：
def average(lst):
    return sum(lst) / len(lst)

示例 3：
描述：检查数字是否为偶数
代码：
def is_even(n):
    return n % 2 == 0

现在请生成：
描述：计算数字的阶乘
代码：
"""

# 输出：
# def factorial(n):
#     if n == 0:
#         return 1
#     return n * factorial(n - 1)
```

### Few-shot 优势

✅ **准确度高**
- 通过示例学习模式
- 减少误解
- 输出质量稳定

✅ **格式可控**
- 示例定义输出格式
- 保持一致性
- 易于后处理

✅ **适用性广**
- 复杂任务也能处理
- 新任务快速适应
- 灵活调整

### Few-shot 局限性

❌ **Token 消耗大**
- 示例占用空间
- 增加成本
- 上下文限制

❌ **示例选择关键**
- 需要精心选择
- 质量影响效果
- 准备工作量大

❌ **上下文限制**
- 示例数量受限
- 长文本处理困难
- 需要权衡

## 🔄 对比分析

### 性能对比

| 指标 | Zero-shot | Few-shot |
|------|-----------|----------|
| 准确度 | 中等 | 高 |
| Token 消耗 | 低 | 高 |
| 实现难度 | 简单 | 中等 |
| 适用范围 | 有限 | 广泛 |
| 稳定性 | 波动大 | 稳定 |

### 适用场景对比

| 场景 | 推荐方法 | 原因 |
|------|---------|------|
| 简单分类 | Zero-shot | 任务明确，无需示例 |
| 格式要求严格 | Few-shot | 示例定义格式 |
| 复杂推理 | Few-shot | 需要多步指导 |
| 快速原型 | Zero-shot | 快速迭代 |
| 生产环境 | Few-shot | 质量稳定 |
| 成本敏感 | Zero-shot | 节省 Token |

## 🎨 高级技巧

### 1. 示例选择策略

**多样性**
```python
# 好的示例：覆盖不同情况
examples = [
    ("正面情感", "积极"),
    ("负面情感", "消极"),
    ("中性描述", "中性"),
    ("复杂情感", "混合"),
]

# 差的示例：过于单一
examples = [
    ("我很开心", "积极"),
    ("我非常开心", "积极"),
    ("我特别开心", "积极"),
]
```

**代表性**
```python
# 选择有代表性的示例
# 覆盖任务的各个方面
# 避免特殊情况
```

**质量优先**
```python
# 选择高质量的示例
# 避免模糊不清的例子
# 确保示例准确无误
```

### 2. 示例数量优化

**经验法则**
- 简单任务：1-3 个示例
- 中等任务：3-6 个示例
- 复杂任务：6-10 个示例

**测试不同数量**
```python
# 测试不同示例数量的效果
for n in [1, 3, 5, 7, 10]:
    result = test_with_n_examples(n)
    print(f"{n} examples: {result.accuracy}")
```

### 3. 示例格式设计

**清晰标注**
```python
# 好的格式
"""
示例 1：
输入：[文本]
输出：[结果]

示例 2：
输入：[文本]
输出：[结果]
"""

# 差的格式
"""
[文本] -> [结果]
[文本] -> [结果]
"""
```

**一致性**
```python

# 使用相同的标注
# 统一的命名规范
```

## 💡 最佳实践

### 1. 从 Zero-shot 开始

```python
# 先尝试 Zero-shot
result = zero_shot_prompt(task)

# 如果效果不好，再添加示例
if result.quality < threshold:
    result = few_shot_prompt(task, examples)
```

### 2. 逐步增加示例

```python
# 从少量示例开始
examples = select_top_k_examples(all_examples, k=3)

# 逐步增加直到达到目标
while len(examples) < max_examples:
    result = test_with_examples(examples)
    if result.quality >= target_quality:
        break
    examples.append(select_next_example(all_examples, examples))
```

### 3. 混合使用

```python
# 结合 Zero-shot 和 Few-shot
prompt = f"""
{task_description}

{few_examples}

{new_task}
"""

# 利用 Few-shot 的模式
# 保持 Zero-shot 的灵活性
```
