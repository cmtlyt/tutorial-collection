## 📖 概述

Context Management（上下文管理）是 Prompt Engineering 中的关键技术，涉及如何有效地组织、传递和管理对话历史和相关信息，以优化模型的理解能力和输出质量。

## 🎯 核心概念

### 什么是 Context Management？

**定义**：在多轮对话中，有效地管理和传递相关的历史信息、背景知识和上下文，使模型能够理解当前对话的完整语境。

**核心挑战**：
- 上下文窗口限制
- 信息筛选和压缩
- 相关性判断
- 对话连贯性

### 为什么重要？

1. **理解对话历史**
   - 维持对话连贯性
   - 理解指代关系
   - 保持话题一致性

2. **提高响应质量**
   - 提供必要的背景
   - 避免重复询问
   - 生成更准确的回答

3. **优化 Token 使用**
   - 高效利用上下文窗口
   - 减少无关信息
   - 降低成本

### 1. 完整历史传递

```python
# 传递完整对话历史
def get_full_context(conversation_history):
    """
    获取完整对话上下文
    """
    context = ""
    for message in conversation_history:
        role = message["role"]  # user/assistant
        content = message["content"]
        context += f"{role}: {content}\n"
    
    return context

# 使用
prompt = f"""
对话历史：
{get_full_context(conversation_history)}

当前问题：{current_question}
"""
```

def hierarchical_context(history, current_query):
    """
    分层上下文管理
    """
    # 第一层：系统提示
    system_prompt = "你是一个专业的助手..."
    
    # 第二层：长期记忆（摘要）
    long_term = get_long_term_memory()
    
    # 第三层：相关历史

    # 第四层：当前查询

    return {
        "system": system_prompt,
        "long_term": long_term,
        "relevant": relevant,
        "current": current
    }

# 使用
context = hierarchical_context(conversation_history, current_question)
prompt = f"""
{context['system']}

长期记忆：
{context['long_term']}

相关对话：
{context['relevant']}

当前问题：
{context['current']}
"""

### 2. 动态上下文调整

```python
def dynamic_context_adjustment(history, current_query, max_tokens=4000):
    """
    动态调整上下文大小
    """
    # 估算每个部分的 Token 数
    system_tokens = estimate_tokens(system_prompt)
    query_tokens = estimate_tokens(current_query)
    
    # 计算可用 Token 数
    available_tokens = max_tokens - system_tokens - query_tokens
    
    # 根据可用 Token 数调整历史上下文
    if available_tokens < 1000:
        # Token 不足，使用摘要
        context = summarize_context(history)
    elif available_tokens < 2000:
        # Token 有限，使用滑动窗口
        context = sliding_window_context(history, window_size=2)
    else:
        # Token 充足，使用完整历史
        context = format_context(history)
    
    return context
```

def topic_aware_context(history, current_query):
    """
    基于主题的上下文管理
    """
    # 识别当前主题
    current_topic = identify_topic(current_query)

## 💡 最佳实践

### 1. 上下文窗口管理

```python
def manage_context_window(history, current_query, max_tokens=4000):
    """
    管理上下文窗口
    """
    # 1. 系统提示（固定）
    system_prompt = get_system_prompt()
    system_tokens = count_tokens(system_prompt)
    
    # 2. 当前查询（必需）
    query_tokens = count_tokens(current_query)
    
    # 3. 计算可用 Token
    available_tokens = max_tokens - system_tokens - query_tokens
    
    # 4. 根据可用 Token 选择策略
    if available_tokens < 500:
        # Token 严重不足，只保留最近 1 轮
        context = format_context(history[-1:])
    elif available_tokens < 1500:
        # Token 有限，使用摘要
        context = summarize_context(history)
    elif available_tokens < 3000:
        # Token 充足，使用滑动窗口
        context = sliding_window_context(history, window_size=3)
    else:
        # Token 很充足，使用完整历史
        context = format_context(history)
    
    return {
        "system": system_prompt,
        "context": context,
        "query": current_query
    }
```

### 2. 信息优先级

```python
def prioritize_context(history, current_query):
    """
    优先级排序上下文
    """
    scored_messages = []
    
    for message in history:
        # 计算多个维度的重要性
        recency_score = calculate_recency(message, history)
        relevance_score = calculate_relevance(message["content"], current_query)
        importance_score = calculate_importance(message["content"])
        
        # 加权总分
        total_score = (
            recency_score * 0.3 +
            relevance_score * 0.5 +
            importance_score * 0.2
        )
        
        scored_messages.append({
            "message": message,
            "score": total_score
        })
    
    # 按分数排序
    scored_messages.sort(key=lambda x: x["score"], reverse=True)
    
    # 选择前 N 个
    selected = [item["message"] for item in scored_messages[:5]]
    
    return format_context(selected)
```

### 3. 上下文验证

```python
def validate_context(context, current_query):
    """
    验证上下文的有效性
    """
    # 检查上下文是否相关
    relevance = calculate_context_relevance(context, current_query)
    
    # 检查上下文是否一致
    consistency = check_context_consistency(context)
    
    # 检查上下文是否过时
    freshness = check_context_freshness(context)
    
    if relevance < 0.3:
        return {
            "valid": False,
            "reason": "上下文相关性低",
            "suggestion": "使用更少的历史信息"
        }
    
    if consistency < 0.5:
        return {
            "valid": False,
            "reason": "上下文存在矛盾",
            "suggestion": "清理矛盾的历史信息"
        }
    
    if freshness < 0.4:
        return {
            "valid": False,
            "reason": "上下文信息过时",
            "suggestion": "使用更近期的对话"
        }
    
    return {"valid": True}
```

### 4. 上下文压缩

```python
def compress_context(history, compression_ratio=0.5):
    """
    压缩上下文
    """
    # 计算目标长度
    target_length = int(len(history) * compression_ratio)
    
    # 选择最重要的消息
    scored_messages = []
    for message in history:
        score = calculate_importance(message["content"])
        scored_messages.append((message, score))
    
    # 按重要性排序并选择
    scored_messages.sort(key=lambda x: x[1], reverse=True)
    selected = [msg for msg, score in scored_messages[:target_length]]
    
    # 按时间顺序排列
    selected.sort(key=lambda x: x["timestamp"])
    
    return format_context(selected)
```

## ⚠️ 注意事项

### 1. Token 限制

上下文窗口有限制：
- GPT-3.5: 4K tokens
- GPT-4: 8K-32K tokens
- Claude: 200K tokens
- 需要根据模型调整策略

### 2. 信息丢失

过度压缩可能导致信息丢失：
- 关键细节可能丢失
- 上下文连贯性受损
- 需要平衡压缩和完整性

### 3. 计算成本

复杂的上下文管理增加成本：
- 需要额外的 API 调用
- 增加计算时间
- 需要权衡成本和效果
