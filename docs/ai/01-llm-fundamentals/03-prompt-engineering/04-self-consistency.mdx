# Self-Consistency

> **版本**：v1.1  
> **最后更新**：2026-04-16

## 📖 概述

Self-Consistency（自洽性）是一种基于 Chain of Thought 的增强技术，通过生成多个独立的推理路径并选择最一致的答案，显著提升复杂推理任务的准确度。

## 🎯 核心概念

### 什么是 Self-Consistency？

**定义**：对同一个问题生成多个不同的推理路径，然后通过投票机制选择出现频率最高的答案。

**核心思想**：
- 一次推理可能出错
- 多次独立推理增加可靠性
- 多数答案更可能是正确的
- 类似于"三个臭皮匠，顶个诸葛亮"

### 为什么有效？

1. **减少随机性**
   - 语言模型生成具有随机性
   - 多次采样覆盖更多可能性
   - 降低偶然错误的影响

2. **自我验证**
   - 不同推理路径相互验证
   - 一致的答案更可信
   - 发现并排除错误答案

3. **提高鲁棒性**
   - 对噪声更不敏感
   - 处理歧义问题更好
   - 整体性能更稳定

## 💡 工作原理

### 基本流程

```
1. 输入问题
   ↓
2. 生成 N 个独立推理路径
   ↓
3. 提取每个路径的答案
   ↓
4. 统计答案分布
   ↓
5. 选择出现次数最多的答案
```

### 伪代码实现

```python
def self_consistency(problem, n_samples=5):
    """
    Self-Consistency 推理
    
    参数:
        problem: 待解决的问题
        n_samples: 生成推理路径的数量
    
    返回:
        最终答案和推理过程
    """
    answers = []
    reasoning_paths = []
    
    # 生成多个推理路径
    for i in range(n_samples):
        # 使用 Chain of Thought 生成推理
        reasoning, answer = generate_cot_reasoning(problem)
        answers.append(answer)
        reasoning_paths.append(reasoning)
    
    # 统计答案分布
    answer_counts = {}
    for ans in answers:
        answer_counts[ans] = answer_counts.get(ans, 0) + 1
    
    # 选择出现次数最多的答案
    final_answer = max(answer_counts.items(), key=lambda x: x[1])[0]
    
    return {
        "answer": final_answer,
        "confidence": answer_counts[final_answer] / n_samples,
        "all_answers": answer_counts,
        "reasoning_paths": reasoning_paths
    }
```

def self_consistency_with_temperature(problem, n_samples=5, temperature=0.7):

### 2. 分层推理

```python
def hierarchical_self_consistency(problem):
    """
    分层 Self-Consistency
    
    先生成多个推理策略
    对每个策略生成多个推理路径
    """
    # 生成多个推理策略
    strategies = generate_reasoning_strategies(problem, n=3)
    
    all_answers = []
    for strategy in strategies:
        # 对每个策略生成多个推理
        for i in range(3):
            reasoning, answer = apply_strategy(problem, strategy)
            all_answers.append(answer)
    
    # 选择最一致的答案
    return select_consistent_answer(all_answers)
```

### 3. 自适应采样

```python
def adaptive_self_consistency(problem, max_samples=10, confidence_threshold=0.8):
    """
    自适应 Self-Consistency
    
    根据置信度动态调整采样数量
    """
    answers = []
    
    for i in range(max_samples):
        reasoning, answer = generate_cot_reasoning(problem)
        answers.append(answer)
        
        # 计算当前置信度
        confidence = calculate_confidence(answers)
        
        # 如果置信度足够高，提前停止
        if confidence >= confidence_threshold and len(answers) >= 3:
            break
    
    return select_consistent_answer(answers)
```

### 4. 加权投票

```python
def weighted_self_consistency(problem, n_samples=5):
    """
    加权投票的 Self-Consistency
    
    根据推理质量加权投票
    """
    results = []
    for i in range(n_samples):
        reasoning, answer = generate_cot_reasoning(problem)
        quality = evaluate_reasoning_quality(reasoning)
        results.append({
            "answer": answer,
            "reasoning": reasoning,
            "weight": quality
        })
    
    # 加权投票
    answer_weights = {}
    for result in results:
        ans = result["answer"]
        weight = result["weight"]
        answer_weights[ans] = answer_weights.get(ans, 0) + weight
    
    # 选择权重最高的答案
    final_answer = max(answer_weights.items(), key=lambda x: x[1])[0]
    
    return final_answer
```

### 3. 处理无共识情况

```python
def handle_no_consensus(answers):
    """
    处理没有明显共识的情况
    """
    if max(answers.values()) / sum(answers.values()) < 0.5:
        # 没有明显的多数答案
        return {
            "status": "no_consensus",
            "message": "推理路径分歧较大，需要更多信息",
            "all_answers": answers
        }
    else:
        # 有明确的多数答案
        final_answer = max(answers.items(), key=lambda x: x[1])[0]
        return {
            "status": "success",
            "answer": final_answer
        }
```

## ⚠️ 注意事项

### 1. Token 消耗

Self-Consistency 会显著增加 Token 消耗：
- 每个样本都需要完整的推理
- 成本与采样数量成正比
- 需要权衡准确度和成本

**建议**：
- 对于关键任务，使用更多样本
- 对于日常任务，使用 3-5 个样本
- 考虑使用缓存避免重复计算

### 2. 延迟增加

生成多个推理路径会增加延迟：
- 串行生成：延迟 = n × 单次延迟
- 并行生成：延迟 ≈ 单次延迟（需要并发支持）

**建议**：
- 使用并行生成减少延迟
- 对实时性要求高的任务谨慎使用
- 考虑预生成常见问题的答案

### 3. 适用范围

Self-Consistency 不是万能的：

**适合的场景**：
- 数学计算
- 逻辑推理
- 代码生成
- 需要准确答案的任务

**不适合的场景**：
- 创意写作
- 开放式问题
- 需要多样性的任务
- 成本敏感的场景
