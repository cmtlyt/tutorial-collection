# cargo-outdated 依赖更新

> **版本**：v1.0  
> **最后更新**：2026-04-22

## 📚 概念介绍

[cargo-outdated](https://github.com/kbknapp/cargo-outdated) 用于检查项目依赖是否有新版本可用。它会对比 `Cargo.toml` 中声明的版本要求与 crates.io 上的最新版本，帮助你及时更新依赖，获取新功能和安全修复。

## 🎯 安装与使用

### 基本用法

```bash
# 安装 cargo-outdated
cargo install cargo-outdated

# 检查过时的依赖
cargo outdated

# 仅显示根依赖（不显示传递依赖）
cargo outdated --root-deps-only

# 显示所有依赖（包括传递依赖）
cargo outdated --depth 999

# 在 workspace 中运行
cargo outdated --workspace
```

### 输出示例

```
Name             Project  Compat  Latest  Kind    Platform
----             -------  ------  ------  ----    --------
clap             4.4.0    4.4.18  4.5.1   Normal  ---
serde            1.0.190  1.0.200 1.0.200 Normal  ---
tokio            1.33.0   1.35.0  1.36.0  Normal  ---
rand             ---      ---     0.9.0   Normal  ---
```

### 列含义说明

| 列 | 说明 |
|------|------|
| **Project** | 当前 `Cargo.lock` 中使用的版本 |
| **Compat** | 在当前版本要求范围内的最新兼容版本 |
| **Latest** | crates.io 上的绝对最新版本 |
| **Kind** | 依赖类型（Normal / Development / Build） |

## 🔄 更新策略

### 安全更新（兼容范围内）

当 **Compat** 列有更新版本时，说明在当前 `Cargo.toml` 的版本要求范围内有新版本：

```bash
# 更新到兼容范围内的最新版本（只更新 Cargo.lock）
cargo update

# 更新特定依赖
cargo update -p serde
```

### 主版本更新

当 **Latest** 列显示的版本超出了当前版本要求范围，需要手动修改 `Cargo.toml`：

```bash
# 使用 cargo add 更新到最新版本（会修改 Cargo.toml）
cargo add clap@4.5
cargo add tokio@1.36
```

### 更新工作流

```bash
# 1. 查看过时的依赖
cargo outdated --root-deps-only

# 2. 先更新兼容范围内的版本
cargo update

# 3. 运行测试确保没有问题
cargo test

# 4. 对需要主版本更新的依赖，查看 CHANGELOG
# 5. 逐个更新并测试
cargo add some-crate@new-version
cargo test
```

## 📊 结合其他工具

### 对比 `cargo update --dry-run`

```bash
# cargo update 的 dry-run 模式也能显示可更新的依赖
cargo update --dry-run
```

`cargo outdated` 的优势在于：
- 同时显示兼容版本和最新版本
- 区分根依赖和传递依赖
- 输出更易读的表格格式

### 与 Dependabot / Renovate 对比

| 工具 | 方式 | 适用场景 |
|------|------|----------|
| `cargo outdated` | 本地命令行 | 手动检查和评估 |
| Dependabot | 自动 PR | GitHub 上的自动化更新 |
| Renovate | 自动 PR | 支持更多平台和定制化 |
