# crates.io 发布流程

> **版本**：v1.0  
> **最后更新**：2026-04-22

## 📚 概念介绍

[crates.io](https://crates.io) 是 Rust 的官方包注册中心。发布 crate 到 crates.io 后，任何人都可以通过 `cargo add` 或 `Cargo.toml` 将其添加为依赖。本节讲解从准备到发布的完整流程。

## 🎯 发布前准备

### 完善 Cargo.toml 元数据

发布到 crates.io 需要提供完整的元数据信息：

```toml
[package]
name = "my-awesome-crate"
version = "0.1.0"
edition = "2021"
rust-version = "1.70"

# --- 以下字段是发布所必需的 ---

# 简短描述（会显示在 crates.io 搜索结果中）
description = "一个高性能的字符串处理工具库"

# 许可证（SPDX 表达式）
license = "MIT OR Apache-2.0"

# 或者指定许可证文件
# license-file = "LICENSE"

# --- 以下字段强烈推荐填写 ---

# 项目仓库地址
repository = "https://github.com/username/my-awesome-crate"

# 项目主页
homepage = "https://github.com/username/my-awesome-crate"

# 文档地址（不填则默认指向 docs.rs）
documentation = "https://docs.rs/my-awesome-crate"

# README 文件路径
readme = "README.md"

# 关键词（最多 5 个，用于搜索）
keywords = ["string", "text", "utility", "processing"]

# 分类（从 crates.io/category_slugs 中选择）
categories = ["text-processing", "command-line-utilities"]

# 排除不需要打包的文件
exclude = [
    "tests/",
    "benches/",
    ".github/",
    "examples/large-dataset/",
]

# 或者只包含指定文件
# include = ["src/**/*", "Cargo.toml", "README.md", "LICENSE*"]
```

### 检查清单

```bash
# 1. 确保代码能编译
cargo build

# 2. 确保所有测试通过
cargo test

# 3. 确保文档能生成
cargo doc --no-deps

# 4. 检查打包内容（不实际发布）
cargo package --list

# 5. 模拟发布（检查元数据是否完整）
cargo publish --dry-run
```

## 🔄 账号与认证

### 获取 API Token

1. 访问 [crates.io](https://crates.io) 并用 GitHub 账号登录
2. 进入 **Account Settings** → **API Tokens**
3. 创建一个新的 Token

```bash
# 登录 crates.io
cargo login <your-api-token>

# Token 会保存在 ~/.cargo/credentials.toml
```

:::warning
API Token 具有发布权限，请妥善保管。建议在 CI 中使用环境变量传递，不要写入代码仓库。
:::

## 🎯 执行发布

### 首次发布

```bash
# 发布到 crates.io
cargo publish
```

发布后：
- crate 立即出现在 `https://crates.io/crates/<name>`
- docs.rs 会在几分钟内自动构建文档
- 其他用户可以通过 `cargo add <name>` 安装

### 更新已有 crate

```bash
# 1. 修改 Cargo.toml 中的 version
# 2. 更新 CHANGELOG
# 3. 提交并打 tag
git commit -am "release: v0.2.0"
git tag v0.2.0
git push && git push --tags

# 4. 发布新版本
cargo publish
```

## 📊 Crate 命名规范

| 规则 | 示例 |
|------|------|
| 使用小写字母和连字符 | `my-crate`（不是 `my_crate` 或 `MyCrate`） |
| 不要使用通用名称 | 避免 `utils`、`helper`、`core` 等 |
| 避免名称抢注 | 不要注册你不打算维护的名称 |
| 组织前缀 | `tokio-stream`、`serde-json` |

:::warning
**发布到 crates.io 的 crate 无法删除**（只能 yank 使其不再出现在搜索结果中），请确认名称和内容无误后再发布。
:::

## 🏗️ Yank：撤回版本

如果发布了有问题的版本，可以使用 yank 将其标记为不推荐使用：

```bash
# 撤回特定版本（已依赖此版本的项目仍可继续使用）
cargo yank --version 0.1.1

# 取消撤回
cargo yank --version 0.1.1 --undo
```

yank 的效果：
- 不会从 crates.io 删除该版本
- 新项目无法将其添加为依赖
- 已有的 `Cargo.lock` 中引用此版本的项目不受影响
