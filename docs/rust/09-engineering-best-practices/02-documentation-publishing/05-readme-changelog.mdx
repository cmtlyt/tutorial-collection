# README 与 CHANGELOG

> **版本**：v1.0  
> **最后更新**：2026-04-22

## 📚 概念介绍

README 和 CHANGELOG 是项目级别的文档，不同于 API 文档（rustdoc）。README 是用户接触你项目的**第一印象**，CHANGELOG 则是版本间变更的**完整记录**。crates.io 会在 crate 页面直接展示 README 的内容。

## 🎯 编写高质量的 README

### README 结构模板

一个优秀的 Rust 项目 README 通常包含以下部分：

```markdown
# my-awesome-crate

[![Crates.io](https://img.shields.io/crates/v/my-awesome-crate.svg)](https://crates.io/crates/my-awesome-crate)
[![Documentation](https://docs.rs/my-awesome-crate/badge.svg)](https://docs.rs/my-awesome-crate)
[![License](https://img.shields.io/crates/l/my-awesome-crate.svg)](LICENSE)

一句话描述：这个 crate 做什么。

## 功能特性

- ✅ 功能 A：简要说明
- ✅ 功能 B：简要说明
- ✅ 功能 C：简要说明

## 安装

在 `Cargo.toml` 中添加依赖：

\```toml
[dependencies]
my-awesome-crate = "0.1"
\```

或使用 cargo add：

\```bash
cargo add my-awesome-crate
\```

\```

## 🔄 编写 CHANGELOG

### Keep a Changelog 规范

推荐使用 [Keep a Changelog](https://keepachangelog.com) 格式：

```markdown
# Changelog

本项目所有重要变更都记录在此文件中。

格式基于 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，
本项目遵循 [语义化版本](https://semver.org/lang/zh-CN/) 规范。

## [Unreleased]

### Added
- 新增 `Widget::render_async` 异步渲染方法

## [0.2.0] - 2026-04-20

### Added
- 新增 `serde` feature，支持序列化和反序列化
- 新增 `Widget::from_config` 从配置文件创建组件

### Changed
- `Widget::new` 的参数从 `String` 改为 `&str`

### Deprecated
- `Widget::create` 已弃用，请使用 `Widget::new`

### Fixed
- 修复在空字符串输入时的 panic 问题 (#42)

## [0.1.0] - 2026-03-15

### Added
- 初始版本发布
- `Widget` 结构体及基本操作方法
- `render` 方法支持 HTML 和文本输出
```

### 变更类型说明

| 类型 | 说明 |
|------|------|
| **Added** | 新增的功能 |
| **Changed** | 对已有功能的变更 |
| **Deprecated** | 即将被移除的功能 |
| **Removed** | 已移除的功能 |
| **Fixed** | Bug 修复 |
| **Security** | 安全相关的修复 |

## 🏗️ 自动化 CHANGELOG

### 使用 git-cliff 自动生成

[git-cliff](https://git-cliff.org) 可以基于 Git 提交历史自动生成 CHANGELOG：

```bash
# 安装 git-cliff
cargo install git-cliff

# 生成 CHANGELOG
git cliff --output CHANGELOG.md

# 只生成最新版本的变更
git cliff --latest --output CHANGELOG.md

# 预览下一个版本
git cliff --unreleased
```

配置文件 `cliff.toml`：

```toml
[changelog]
header = """
# Changelog\n
"""
body = """
{% for group, commits in commits | group_by(attribute="group") %}
### {{ group | upper_first }}
{% for commit in commits %}
- {{ commit.message | upper_first }}\
{% endfor %}
{% endfor %}\n
"""
trim = true

[git]
conventional_commits = true
filter_unconventional = true
commit_parsers = [
    { message = "^feat", group = "Added" },
    { message = "^fix", group = "Fixed" },
    { message = "^doc", group = "Documentation" },
    { message = "^perf", group = "Performance" },
    { message = "^refactor", group = "Changed" },
]
```

### 配合约定式提交

搭配 [Conventional Commits](https://www.conventionalcommits.org) 规范使用效果最佳：

```bash
# 提交格式
git commit -m "feat: 新增异步渲染方法"
git commit -m "fix: 修复空字符串 panic 问题"
git commit -m "docs: 更新 README 安装说明"
git commit -m "feat!: 变更 Widget::new 参数类型（破坏性变更）"
```
