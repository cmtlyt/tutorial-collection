# PGO（配置文件引导优化）

> **版本**：v1.0  
> **最后更新**：2026-04-22

## 📚 概念介绍

**PGO（Profile-Guided Optimization，配置文件引导优化）** 是一种利用程序运行时的性能数据来指导编译器优化决策的技术。传统编译器只能基于静态代码分析做出优化选择，而 PGO 让编译器知道哪些代码路径是热点、哪些分支更常被执行，从而做出更精准的优化。

PGO 的工作流程分三步：
1. **Instrumentation（插桩编译）**：编译一个带有性能采集探针的版本
2. **Profiling（运行采集）**：运行插桩版本，收集运行时性能数据
3. **Optimization（优化编译）**：使用采集的数据重新编译，指导优化

## 🎯 PGO 的工作原理

### 三步流程

```bash
# 第一步：插桩编译
# 生成带有性能采集探针的二进制
RUSTFLAGS="-Cprofile-generate=/tmp/pgo-data" \
    cargo build --release --target=x86_64-unknown-linux-gnu

# 第二步：运行采集
# 使用真实或代表性的工作负载运行程序
./target/x86_64-unknown-linux-gnu/release/my_app --typical-workload
# 可以多次运行不同的工作负载场景
./target/x86_64-unknown-linux-gnu/release/my_app --another-workload

# 合并性能数据
llvm-profdata merge -o /tmp/pgo-data/merged.profdata /tmp/pgo-data/

# 第三步：使用性能数据重新编译
RUSTFLAGS="-Cprofile-use=/tmp/pgo-data/merged.profdata -Cllvm-args=-pgo-warn-missing-function" \
    cargo build --release --target=x86_64-unknown-linux-gnu
```

## 🔧 完整的 PGO 脚本

### 自动化脚本

```bash
#!/bin/bash
# pgo-build.sh — 自动化 PGO 构建脚本

set -euo pipefail

PROJECT_NAME="my_app"
TARGET="x86_64-unknown-linux-gnu"
PGO_DATA_DIR="/tmp/pgo-data-${PROJECT_NAME}"

echo "=== PGO 构建流程 ==="

# 清理旧数据
rm -rf "${PGO_DATA_DIR}"
mkdir -p "${PGO_DATA_DIR}"

# 第一步：插桩编译
echo "[1/3] 插桩编译..."
RUSTFLAGS="-Cprofile-generate=${PGO_DATA_DIR}" \
    cargo build --release --target="${TARGET}"

# 第二步：运行采集
echo "[2/3] 运行性能采集..."
# 替换为你的实际工作负载
"./target/${TARGET}/release/${PROJECT_NAME}" --benchmark-mode || true

# 合并数据
echo "合并性能数据..."
llvm-profdata merge -o "${PGO_DATA_DIR}/merged.profdata" "${PGO_DATA_DIR}/"

# 第三步：优化编译
echo "[3/3] PGO 优化编译..."
RUSTFLAGS="-Cprofile-use=${PGO_DATA_DIR}/merged.profdata" \
    cargo build --release --target="${TARGET}"

echo "=== PGO 构建完成 ==="
echo "输出: ./target/${TARGET}/release/${PROJECT_NAME}"
```

### 可以被 PGO 优化的示例程序

```rs
use std::collections::HashMap;
use std::time::Instant;

// 模拟一个有多种代码路径的程序
fn process_request(request_type: &str, data: &[u8]) -> String {
    match request_type {
        // 假设 80% 的请求是 "query" 类型
        // PGO 会让编译器优先处理这个分支
        "query" => {
            let sum: u64 = data.iter().map(|&b| b as u64).sum();
            format!("查询结果: {}", sum)
        }
        // 15% 是 "update" 类型
        "update" => {
            let max = data.iter().max().copied().unwrap_or(0);
            format!("更新完成: max={}", max)
        }
        // 5% 是其他类型
        _ => {
            format!("未知请求: {}", request_type)
        }
    }
}

fn parse_and_lookup(input: &str, table: &HashMap<String, i32>) -> i32 {
    // PGO 会知道大多数查找都是命中的
    match table.get(input) {
        Some(&value) => value * 2,
        None => -1,
    }
}

fn main() {
    // 构建查找表
    let mut table = HashMap::new();
    for i in 0..1000 {
        table.insert(format!("key_{}", i), i);
    }

    let iterations = 1_000_000;
    let data: Vec<u8> = (0..100).collect();

    let start = Instant::now();

    let mut total = 0i64;
    for i in 0..iterations {
        // 模拟真实的请求分布
        let request_type = if i % 100 < 80 {
            "query"
        } else if i % 100 < 95 {
            "update"
        } else {
            "other"
        };

        let result = process_request(request_type, &data);
        total += result.len() as i64;

        // 查找操作
        let key = format!("key_{}", i % 1000);
        total += parse_and_lookup(&key, &table) as i64;
    }

    let elapsed = start.elapsed();
    println!("{}次迭代: {:?}", iterations, elapsed);
    println!("total = {}", total);
    println!("\nPGO 能让编译器知道:");
    println!("  - 80% 的请求走 'query' 分支");
    println!("  - HashMap::get 大部分时候返回 Some");
    println!("  - 热循环中的函数应该被内联");
}
```

## 🔗 相关概念

- **编译器优化级别**：PGO 在 opt-level 2 或 3 之上提供额外优化
- **LTO**：PGO + LTO 可以叠加使用，效果更佳
- **flamegraph**：火焰图可以验证 PGO 的优化效果
- **criterion**：基准测试可以量化 PGO 的性能提升
