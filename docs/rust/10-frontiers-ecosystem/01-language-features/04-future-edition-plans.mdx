# 未来 Edition 规划

> **版本**：v1.0  
> **最后更新**：2026-04-23

## 📚 概念介绍

Rust 遵循三年一次的 Edition 发布节奏（2015 → 2018 → 2021 → 2024）。下一个 Edition 预计将是 **Rust 2027 Edition**。本节将介绍 Rust Edition 的演进机制、未来可能纳入的特性方向，以及如何跟踪语言发展动态。

## 🎯 Edition 发布节奏

### 时间线回顾

| Edition | 发布时间 | 对应 Rust 版本 | 关键主题 |
|---------|---------|---------------|---------|
| 2015 | 2015-05 | 1.0 | 初始稳定版 |
| 2018 | 2018-12 | 1.31 | 模块系统改革、NLL、async/await 基础 |
| 2021 | 2021-10 | 1.56 | 闭包不相交捕获、prelude 扩展 |
| 2024 | 2025-02 | 1.85 | RPIT 生命周期、unsafe extern、let 链 |
| 2027 | ~2028 | 待定 | 规划中 |

### Edition 设计原则

```
                 Edition 的核心约束
┌──────────────────────────────────────────┐
│  1. 向后兼容：旧代码在新编译器上仍能编译  │
│  2. 跨 Edition 互操作：不同 Edition 的    │
│     crate 可以互相依赖                    │
│  3. 自动迁移：cargo fix --edition 提供    │
│     自动化迁移路径                        │
│  4. 非破坏性：只有在无法通过其他方式引入   │
│     时才使用 Edition 门控                 │
└──────────────────────────────────────────┘
```

### 可能的 Edition 变更

```rust
// Edition 变更只用于必须打破向后兼容性的场景
// 以下是可能需要 Edition 门控的方向：

// 1. 新的关键字保留
//    - 为生成器相关语法保留关键字
//    - 可能为效果系统（effect system）保留语法

// 2. 模式匹配进一步严格化
//    - 更严格的穷尽性检查
//    - 新的模式语法

// 3. 生命周期推断改进
//    - 更智能的生命周期省略规则
//    - 减少不必要的生命周期标注

fn main() {
    // 大多数新特性不需要 Edition 门控
    // 它们可以直接在稳定版中添加（向后兼容的方式）
    println!("Edition 变更是最后手段，大多数改进直接加入稳定版");
}
```

## 🔑 非 Edition 特性演进

许多重要特性不需要 Edition 门控，会直接在稳定版中逐步引入：

### 已进行中的特性

```rust
// 以下特性不需要新 Edition，会逐步稳定

// 1. const generics 扩展
// 支持更复杂的 const 表达式
fn create_matrix<const ROWS: usize, const COLS: usize>() -> [[f64; COLS]; ROWS] {
    [[0.0; COLS]; ROWS]
}

// 2. trait upcasting（trait 向上转型）
// 已在 Rust 1.76 稳定
trait Animal {
    fn name(&self) -> &str;
}

trait Dog: Animal {
    fn bark(&self);
}

struct Labrador;

impl Animal for Labrador {
    fn name(&self) -> &str {
        "Labrador"
    }
}

impl Dog for Labrador {
    fn bark(&self) {
        println!("Woof!");
    }
}

fn main() {
    let matrix = create_matrix::<3, 4>();
    println!("矩阵大小: {}x{}", matrix.len(), matrix[0].len());

    let dog: Box<dyn Dog> = Box::new(Labrador);
    dog.bark();

    // trait upcasting: 从 dyn Dog 转为 dyn Animal
    let animal: Box<dyn Animal> = dog;
    println!("动物名: {}", animal.name());
}
```

### 标准库持续改进

```rust
use std::collections::HashMap;

fn main() {
    // LazyLock / LazyCell（Rust 1.80 稳定）
    use std::sync::LazyLock;

    static GLOBAL_CONFIG: LazyLock<HashMap<String, String>> = LazyLock::new(|| {
        let mut map = HashMap::new();
        map.insert("host".into(), "localhost".into());
        map.insert("port".into(), "8080".into());
        map
    });

    println!("配置: {:?}", *GLOBAL_CONFIG);

    // 更多的 const fn 支持
    const BUFFER_SIZE: usize = calculate_buffer_size(1024);
    println!("缓冲区大小: {BUFFER_SIZE}");
}

const fn calculate_buffer_size(base: usize) -> usize {
    base * 2 + 64
}
```

## 🔑 如何跟踪 Rust 发展

### 官方渠道

```
跟踪 Rust 发展的关键渠道
├── RFC 仓库：github.com/rust-lang/rfcs
│   └── 所有重大特性变更的提案和讨论
├── Rust Blog：blog.rust-lang.org
│   └── 官方发布公告和路线图更新
├── This Week in Rust：this-week-in-rust.org
│   └── 每周社区动态汇总
├── Rust Internals：internals.rust-lang.org
│   └── 语言设计讨论论坛
├── Rust 项目目标：rust-lang.github.io/rust-project-goals
│   └── 每半年更新的官方项目目标
└── Nightly Release Notes
    └── 查看最新的 nightly 特性变化
```

### 体验实验性特性

```rust

// 切换到 nightly 工具链
// rustup default nightly

// 在代码中启用特性门控

    // 查看当前编译器版本

    // 查看可用的特性门控
    // rustc -Z help

    println!("但生产代码应使用稳定版");
}
```

### 参与 RFC 流程

```
RFC 流程（参与 Rust 语言演进）
1. Pre-RFC 讨论 → Rust Internals 论坛提出想法
2. RFC 提交 → 在 github.com/rust-lang/rfcs 提交 PR
3. 社区评审 → 广泛讨论，收集反馈
4. FCP（最终评审期）→ 相关团队进行最终决策
5. 接受/拒绝 → 团队投票决定
6. 实现 → 在 nightly 中实现
7. 稳定化 → 经过充分测试后纳入稳定版
```

## 📊 Edition 特性对比总结

| 领域 | 2018 | 2021 | 2024 | 2027（展望） |
|------|------|------|------|------------|
| 模块系统 | 路径简化 | - | - | - |
| 闭包 | - | 不相交捕获 | async 闭包 | - |
| 生命周期 | NLL | - | RPIT 捕获 | 更智能省略 |
| 安全性 | - | - | unsafe extern | 更严格的 unsafe |
| 异步 | async/await 基础 | - | let 链 | async 迭代器 |
| 生成器 | - | - | gen 关键字保留 | gen 块稳定化 |
