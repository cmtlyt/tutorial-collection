# 依赖管理与 crates.io

> **版本**：v1.0  
> **最后更新**：2026-04-22

## 📚 概念介绍

crates.io 是 Rust 的官方包注册中心（package registry），社区中几乎所有的开源库都发布在这里。Cargo 与 crates.io 紧密集成，提供了完善的依赖发现、下载和版本解析功能。理解依赖管理机制是高效使用 Rust 生态的关键。

## 🎯 crates.io 基础

### 搜索和发现

```bash
# 在命令行搜索
cargo search serde

# 查看依赖树
cargo tree

# 查看特定依赖的依赖树
cargo tree -p serde

# 反向查看谁依赖了某个 crate
cargo tree --invert serde
```

你也可以直接在 [crates.io](https://crates.io) 网站上搜索和浏览包，或查看 [docs.rs](https://docs.rs) 上的文档。

### 查看 crate 信息

```bash
# 查看已安装的依赖版本
cargo tree --depth 1

# 查看 crate 的详细信息
cargo info serde
```

## 📦 依赖来源

### 1. crates.io 依赖（默认）

```toml
[dependencies]
serde = "1.0"
```

### 2. Git 仓库依赖

```toml
[dependencies]
# 默认使用 main/master 分支
my-crate = { git = "https://github.com/user/my-crate.git" }

# 指定分支
my-crate = { git = "https://github.com/user/my-crate.git", branch = "develop" }

# 指定 tag
my-crate = { git = "https://github.com/user/my-crate.git", tag = "v1.0.0" }

# 指定 commit
my-crate = { git = "https://github.com/user/my-crate.git", rev = "abc123" }
```

### 3. 本地路径依赖

```toml
[dependencies]
my-local = { path = "../my-local-crate" }
```

### 4. 多来源依赖

发布到 crates.io 时使用版本号，本地开发时使用路径：

```toml
[dependencies]
# 发布时使用 crates.io 版本，本地开发使用 path
my-crate = { version = "0.1.0", path = "../my-crate" }
```

## 🔢 版本号语义

Cargo 使用语义化版本（Semantic Versioning）：

```
主版本号.次版本号.修订号
MAJOR.MINOR.PATCH
```

- **MAJOR**：不兼容的 API 变更
- **MINOR**：向后兼容的功能新增
- **PATCH**：向后兼容的缺陷修复

### 版本要求语法

```toml
[dependencies]
# 插入符号要求（默认行为）
# "1.2.3" 等价于 "^1.2.3"，即 >=1.2.3, <2.0.0
crate-a = "1.2.3"

# 波浪号要求
# ~1.2.3 → >=1.2.3, <1.3.0
crate-b = "~1.2.3"

# 通配符要求
# 1.2.* → >=1.2.0, <1.3.0
crate-c = "1.2.*"

# 精确版本
crate-d = "=1.2.3"

# 比较要求
crate-e = ">=1.2.0"
crate-f = ">1.0.0, <2.0.0"
```

### 特殊规则：0.x 版本

0.x 版本的兼容性规则更严格：

```toml
# "0.1.2" → >=0.1.2, <0.2.0（次版本号变化即视为不兼容）
crate-a = "0.1.2"

# "0.0.3" → >=0.0.3, <0.0.4（修订号变化即视为不兼容）
crate-b = "0.0.3"
```

## 🔒 Cargo.lock

`Cargo.lock` 文件记录了所有依赖的精确版本，确保构建的可重复性：

```bash
# 更新所有依赖到兼容的最新版本（更新 Cargo.lock）
cargo update

# 仅更新指定依赖
cargo update serde

# 更新到精确版本
cargo update serde --precise 1.0.200
```

### 是否应该提交 Cargo.lock

| 项目类型 | 是否提交 | 原因 |
|----------|----------|------|
| 应用程序（binary） | ✅ 提交 | 确保所有环境使用相同版本 |
| 库（library） | ❌ 不提交 | 让下游用户决定具体版本 |

## 🛠️ 依赖管理工具

### cargo add / remove

```bash
# 添加依赖
cargo add serde --features derive
cargo add tokio@1 --features full
cargo add --dev assert_cmd

# 移除依赖
cargo remove serde
```

### cargo-audit：安全审计

```bash
# 安装
cargo install cargo-audit

# 检查已知安全漏洞
cargo audit
```

### cargo-outdated：过期检查

```bash
# 安装
cargo install cargo-outdated

# 检查可更新的依赖
cargo outdated
```

### cargo-deny：依赖策略

```bash
# 安装
cargo install cargo-deny

# 初始化配置
cargo deny init

# 运行检查（许可证、安全、重复依赖等）
cargo deny check
```

## 📝 实际应用示例

### 管理一个典型项目的依赖

```toml
[package]
name = "web-api"
version = "0.1.0"
edition = "2021"

[dependencies]
# Web 框架
axum = "0.7"
tokio = { version = "1", features = ["full"] }
tower-http = { version = "0.5", features = ["cors", "trace"] }

# 序列化
serde = { version = "1.0", features = ["derive"] }
serde_json = "1.0"

# 数据库
sqlx = { version = "0.7", features = ["runtime-tokio", "postgres", "macros"] }

# 错误处理
anyhow = "1.0"
thiserror = "1.0"

# 日志
tracing = "0.1"
tracing-subscriber = { version = "0.3", features = ["env-filter"] }

[dev-dependencies]
reqwest = { version = "0.12", features = ["json"] }
```

```bash
# 查看依赖树
cargo tree --depth 1

# 安全审计
cargo audit

# 检查过期依赖
cargo outdated
```
