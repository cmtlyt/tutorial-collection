  - **React 19 新 Hooks 详细实践**
    - **use API（资源读取）**
      - **功能**：在渲染中读取 Promise 和 Context
      - **Promise 读取**：自动 Suspense 直到 Promise 解析
      - **Context 读取**：支持条件性读取（如早期返回后）
      - **使用限制**：必须在渲染中调用，不能在渲染中创建 Promise
      - **缓存要求**：需要来自支持 Promise 缓存的库或框架
    - **useActionState（Actions 状态管理）**
      - **核心功能**：管理 Actions 的状态，支持副作用
      - **返回值**：`[state, dispatchAction, isPending]`
      - **参数**：`reducerAction, initialState, permalink?`
      - **实践场景**：
        - **表单提交**：处理表单数据提交和状态更新
        - **购物车**：管理添加/删除商品的状态
        - **计数器**：处理递增/递减操作
        - **多类型 Actions**：使用 switch 语句处理不同操作类型
      - **与 useOptimistic 结合**：提供即时 UI 反馈
      - **与表单集成**：作为 `<form action>` 使用，自动处理 Transition
      - **错误处理**：已知错误返回状态，未知错误抛出到 Error Boundary
      - **队列管理**：顺序执行多个 Actions，支持 AbortController 取消
    - **useOptimistic（乐观更新）**
      - **核心功能**：在异步操作期间显示乐观状态
      - **参数**：`(state, updateFunction)`
      - **工作原理**：立即显示乐观状态，操作完成后自动切换回实际状态
      - **实践场景**：
        - **表单提交**：立即显示提交后的状态
        - **点赞/收藏**：立即更新 UI，等待服务器确认
        - **评论发布**：立即显示评论，后台异步提交
        - **购物车**：立即更新数量，等待库存确认
      - **与 Actions 结合**：与 useActionState 配合使用
      - **状态回滚**：操作失败时自动回滚到原始状态
    - **useFormStatus（表单状态访问）**
      - **核心功能**：访问父级表单的提交状态
      - **返回值**：`{ pending, data, method, action }`
      - **使用场景**：
        - **设计系统组件**：在深层子组件中访问表单状态
        - **提交按钮**：根据 pending 状态禁用按钮
        - **加载指示器**：显示表单提交进度
        - **自定义组件**：无需 props drilling 即可访问表单状态
      - **Context 替代**：简化表单状态访问，无需手动 Context
      - **限制**：必须在表单子组件中使用
  - **React 19.2 新 Hooks：useEffectEvent**
    - **核心功能**：分离 Effect 中的事件逻辑
    - **解决问题**：避免事件处理函数变化导致 Effect 重新运行
    - **使用场景**：
      - **通知事件**：聊天室连接成功后显示通知
      - **日志记录**：记录不依赖于 Effect 逻辑的事件
      - **分析事件**：发送分析数据而不触发 Effect 重新运行
    - **最佳实践**：
      - **仅用于事件**：只用于概念上的"事件"，不要滥用
      - **不作为依赖**：Effect Events 不应声明在依赖数组中
      - **位置限制**：必须在同一组件或 Hook 中定义
      - **Linter 集成**：升级 eslint-plugin-react-hooks@latest

## 第九阶段：前沿技术与趋势

### 9.1 React 19+ 新特性
- [ ] React 19 核心特性
  - Actions 系统
  - 新的 Hooks（use、useActionState、useOptimistic）
  - ref 作为 prop
  - Context 作为 provider
  - 改进的 Suspense
  - **文档元数据支持**
    - **原生支持**：直接在组件中渲染 `<title>`、`<link>`、`<meta>` 标签
    - **自动提升**：React 自动将这些标签提升到文档的 `<head>` 部分
    - **组件化元数据**：任何组件都可以定义自己的元数据，提高可组合性
    - **SEO 优化**：简化 SEO 管理，无需手动操作 DOM 或使用第三方库
    - **服务端渲染支持**：在客户端应用、流式 SSR 和 Server Components 中都能正常工作
    - **元数据类型**：
      - `<title>`：页面标题
      - `<meta name="...">`：文档级元数据（关键词、描述、作者等）
      - `<meta itemProp="...">`：特定项目的元数据
      - `<link>`：样式表、图标等链接
    - **使用场景**：
      - 博客文章的 SEO 标签
      - 社交媒体分享卡片
      - 页面描述和关键词
      - 作者信息
  - **样式表支持**
    - **原生集成**：内置对样式表的管理和优化
    - **precedence 属性**：指定样式表的优先级（default、high 等）
    - **自动去重**：React 自动去重相同的样式表，避免重复加载
    - **优先级管理**：根据 precedence 属性自动管理样式表的插入顺序
    - **Suspense 集成**：在 Suspense 边界中正确处理样式表加载
    - **服务端渲染**：SSR 时将样式表包含在 `<head>` 中，确保样式加载后再显示内容
    - **客户端渲染**：客户端渲染时等待新样式表加载完成后再提交渲染
  - **异步脚本支持**
    - **简化使用**：可以在组件树中任何位置渲染异步脚本
    - **自动去重**：即使多个组件渲染相同的脚本，也只加载和执行一次
    - **服务端渲染**：SSR 时将异步脚本包含在 `<head>` 中，优先级低于关键资源
    - **依赖组件**：将脚本放在实际依赖它的组件中，提高代码组织性
  - **资源预加载 API**
    - **prefetchDNS**：预解析 DNS，当可能需要请求该主机时使用
    - **preconnect**：预连接，当确定会请求该主机但不确定具体资源时使用
    - **preload**：预加载资源（字体、样式表等）
    - **preinit**：预初始化资源，加载并执行脚本
    - **性能优化**：显著提升初始页面加载和客户端更新性能
    - **智能优先级**：React 根据资源类型和用途自动优化加载优先级

  - **Activity 组件（性能优化核心）**
    - **核心功能**：隐藏和恢复子组件的 UI 及内部状态
    - **工作原理**：
      - **隐藏模式**：使用 `display: none` CSS 属性视觉隐藏子组件
      - **状态保存**：保存组件内部状态和 DOM，避免状态丢失
      - **副作用清理**：销毁 Effects，清理活动订阅
      - **低优先级渲染**：隐藏时仍响应 props 更新，但优先级较低
      - **状态恢复**：变为可见时恢复之前状态并重新创建 Effects
    - **使用场景**：
      - **状态保存**：隐藏侧边栏但保留展开状态
      - **DOM 保存**：保留表单输入内容（如 textarea 草稿）
      - **预渲染**：提前渲染可能变为可见的内容，减少加载时间
      - **性能优化**：选择性水合，提高页面加载时的交互响应速度
    - **实践案例**：
      - **侧边栏状态保存**：隐藏/显示侧边栏时保持内部状态
      - **标签页切换**：切换标签时保留每个标签的 DOM 状态
      - **后台预渲染**：预加载用户可能访问的页面内容
      - **视频播放器**：隐藏时暂停视频，但保留播放进度
    - **注意事项**：
      - **副作用处理**：隐藏组件的 DOM 副作用会持续存在
      - **Effect 清理**：需要为有副作用的组件添加清理函数
      - **常见标签**：`<video>`、`<audio>`、`<iframe>` 需要特殊处理
      - **StrictMode 集成**：推荐使用 StrictMode 发现问题
  - **useEffectEvent Hook**
    - **核心功能**：分离 Effect 中的事件逻辑
    - **解决问题**：避免因事件处理函数变化导致 Effect 重新运行
    - **使用场景**：Effect 中触发的事件不需要作为依赖项
    - **最佳实践**：只用于概念上的"事件"，不要滥用
  - **cacheSignal（Server Components）**
    - **功能**：了解 cache() 生命周期何时结束
    - **使用场景**：清理或中止不再需要的工作
    - **适用时机**：React 成功完成渲染、渲染中止、渲染失败
  - **Performance Tracks（性能追踪）**
    - **Scheduler 轨道**：
      - **Blocking**：同步更新（用户交互触发）
      - **Transition**：后台非阻塞工作（startTransition 触发）
      - **Suspense**：Suspense 边界相关工作
      - **Idle**：最低优先级工作
    - **Components 轨道**：
      - **火焰图可视化**：显示组件渲染持续时间
      - **Effect 追踪**：显示 effect 执行时间（不同颜色）
      - **生命周期事件**：Mount、Unmount、Reconnect、Disconnect
      - **Props 变更检查**：开发模式下检查不必要的渲染
    - **Server 轨道**：
      - **Server Requests**：可视化 Server Components 中的 Promise
      - **Server Components**：显示服务端组件渲染时长
      - **并行追踪**：支持并发渲染的并行轨道
    - **使用要求**：仅在开发和 profiling 构建中启用
    - **性能影响**：profiling 仪表化会增加额外开销
  - **部分预渲染（Partial Pre-rendering）**
    - **功能**：预渲染应用静态部分，后续恢复渲染动态内容
    - **API**：`prerender`、`resume`、`resumeAndPrerender`
    - **使用场景**：静态内容 CDN 部署 + 动态内容延迟渲染
    - **性能优势**：减少首次加载时间，提升用户体验
  - **Suspense 批处理优化**
    - **功能**：批处理服务端渲染的 Suspense 边界揭示
    - **效果**：更多内容一起显示，对齐客户端渲染行为
    - **View Transitions 准备**：为 View Transitions 提供更好的动画支持
    - **智能策略**：使用启发式算法确保不影响 Core Web Vitals
  - **Web Streams 支持**
    - **Node.js 集成**：Node.js 环境支持 Web Streams
    - **新增 API**：`renderToReadableStream`、`prerender`、`resume`、`resumeAndPrerender`
    - **推荐使用**：Node.js 环境仍推荐使用 Node Streams API
    - **性能优势**：Node Streams 更快，支持默认压缩

    - **Flat Config 默认**：推荐预设使用 flat config
    - **React Compiler 规则**：可选的 React Compiler 支持规则
    - **Legacy Config**：`recommended-legacy` 用于传统配置

- [ ] **React Compiler（自动优化编译器）**
  - **核心功能与原理**
    - **编译时自动优化**：在构建阶段分析组件代码，自动识别可以跳过的渲染和计算
    - **自动 memoization**：自动应用 useMemo、useCallback、React.memo 的等效优化
    - **细粒度响应式**：确保只有真正需要更新的组件才会重新渲染
    - **理解 React 规则**：编译器内置对 React 规则的理解，无需重写代码
  - **优化场景**
    - **跳过级联重渲染**：当父组件更新时，避免不必要的子组件重渲染
    - **优化昂贵计算**：自动缓存组件内部的高开销计算
    - **处理函数引用**：正确处理箭头函数等容易破坏 memoization 的情况
  - **使用指南**
    - **安装与配置**：支持 Babel、Vite、Metro、Rsbuild 等构建工具
    - **React 版本兼容**：支持 React 17、18、19
    - **Next.js 集成**：Next.js 15.3.1+ 支持 swc 调用的 React Compiler
    - **增量采用策略**：可以逐步在现有代码库中启用
  - **与手动优化的关系**
    - **现有代码处理**：保留现有的 useMemo/useCallback 不会改变编译输出
    - **精确控制需求**：在需要精确控制时仍可使用手动优化
    - **新代码建议**：新代码推荐依赖编译器，必要时使用手动优化作为逃生舱
  - **调试与故障排除**
    - **编译器工作原理**：深入理解编译器的分析和优化策略
    - **常见问题排查**：识别和修复使用编译器时可能出现的问题
    - **性能分析**：使用性能分析工具验证优化效果
  - **未来发展趋势**
    - **必需特性**：未来某些 React 特性可能需要编译器才能完全工作
    - **swc/oxc 支持**：正在与 swc 和 oxc 团队合作构建原生支持
    - **生产环境验证**：已在 Meta 等公司生产环境广泛测试
