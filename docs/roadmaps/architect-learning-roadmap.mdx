# 架构师学习路线图

## 第一阶段：编程基础与设计原则

### 1.1 编程语言深入
- [ ] 至少精通一门主流语言
  - Java / Go / C++ / Rust
  - 语言运行时原理（JVM / V8 / GC 机制）
  - 并发编程模型（线程、协程、Actor）
  - 内存管理与性能调优
- [ ] 多语言视野
  - 了解不同语言的设计哲学
  - 掌握各语言适用场景
  - 多范式编程（OOP、FP、响应式）

### 1.2 设计原则
- [ ] SOLID 原则
  - 单一职责原则（SRP）
  - 开闭原则（OCP）
  - 里氏替换原则（LSP）
  - 接口隔离原则（ISP）
  - 依赖反转原则（DIP）
- [ ] 其他重要原则
  - DRY（Don't Repeat Yourself）
  - KISS（Keep It Simple, Stupid）
  - YAGNI（You Aren't Gonna Need It）
  - 关注点分离（Separation of Concerns）
  - 最小知识原则（Law of Demeter）
  - 组合优于继承（Composition over Inheritance）

### 1.3 设计模式
- [ ] 创建型模式
  - 工厂方法（Factory Method）
  - 抽象工厂（Abstract Factory）
  - 建造者（Builder）
  - 单例（Singleton）
  - 原型（Prototype）
- [ ] 结构型模式
  - 适配器（Adapter）
  - 桥接（Bridge）
  - 组合（Composite）
  - 装饰器（Decorator）
  - 外观（Facade）
  - 代理（Proxy）
- [ ] 行为型模式
  - 策略（Strategy）
  - 观察者（Observer）
  - 责任链（Chain of Responsibility）
  - 模板方法（Template Method）
  - 状态（State）
  - 命令（Command）
  - 迭代器（Iterator）

## 学习建议

1. **T 型能力**：在广泛了解各领域的基础上，深耕一到两个方向成为专家
2. **实践驱动**：每学一个架构模式，都尝试在真实项目中落地验证
3. **复盘总结**：定期复盘项目中的架构决策，分析成功与失败的原因
4. **源码阅读**：研读优秀开源项目的架构设计，学习业界最佳实践
5. **业务理解**：架构服务于业务，深入理解业务才能设计出好的架构
6. **权衡思维**：没有银弹，架构设计的核心是在约束条件下做最优取舍
