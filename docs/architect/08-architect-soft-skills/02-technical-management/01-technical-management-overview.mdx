## 🔑 核心概念

### 技术选型评估矩阵

评估一个技术方案时，可以从以下维度打分：

| 维度 | 权重 | 说明 |
|------|------|------|
| **成熟度** | 高 | 社区活跃度、版本稳定性、生产案例 |
| **团队能力** | 高 | 团队是否有学习和使用该技术的能力 |
| **生态兼容** | 中 | 与现有技术栈的兼容性 |
| **性能** | 中 | 是否满足性能需求 |
| **运维成本** | 中 | 部署、监控、故障处理的复杂度 |
| **学习曲线** | 低 | 团队上手所需时间 |
| **社区支持** | 低 | 文档质量、问题解答速度 |

### 技术债务象限

| | 鲁莽 | 谨慎 |
|------|------|------|
| **故意** | "没时间做设计" | "先发布，后重构" |
| **无意** | "分层是什么？" | "现在才知道该怎么做" |
