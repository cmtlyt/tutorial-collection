## 📚 存储引擎

### InnoDB vs MyISAM

| 特性 | InnoDB | MyISAM |
|------|--------|--------|
| 事务支持 | ✓ | ✗ |
| 行级锁 | ✓ | ✗（仅表锁） |
| 外键约束 | ✓ | ✗ |
| 崩溃恢复 | ✓ | ✗ |
| 全文索引 | ✓（5.6+） | ✓ |
| 适用场景 | 高并发、事务型 | 只读、数据仓库 |

### 索引设计原则

```sql
-- 示例：创建合适的索引
-- 1. 在 WHERE、JOIN、ORDER BY 字段上建索引
CREATE INDEX idx_user_email ON users(email);
CREATE INDEX idx_order_status_created ON orders(status, created_at);

-- 2. 联合索引遵循最左前缀原则
-- 这个索引可以支持：(email), (email, status), (email, status, created_at)
CREATE INDEX idx_user_email_status_created ON users(email, status, created_at);

-- 3. 避免在索引列上使用函数
-- 错误示例
SELECT * FROM users WHERE YEAR(created_at) = 2025;

-- 正确示例
SELECT * FROM users WHERE created_at >= '2025-01-01' AND created_at < '2026-01-01';
```

## 📚 事务隔离级别

### 四种隔离级别

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 锁策略 |
|---------|------|----------|------|--------|
| 读未提交 | ✓ | ✓ | ✓ | 最少锁 |
| 读已提交 | ✗ | ✓ | ✓ | 行级锁 |
| 可重复读 | ✗ | ✗ | ✓* | 行锁 + 间隙锁 |
| 串行化 | ✗ | ✗ | ✗ | 表锁 |

*InnoDB 在可重复读级别通过 MVCC + Next-Key Lock 防止幻读

### MVCC（多版本并发控制）

MVCC 通过维护数据的多个版本，实现读写不阻塞：

```js
// MVCC 核心机制
const mvccMechanism = {
  readView: {
    description: "读视图，决定事务能看到的数据版本",
    components: {
      m_ids: "活跃事务 ID 列表",
      min_trx_id: "最小活跃事务 ID",
      max_trx_id: "下一个事务 ID",
      creator_trx_id: "当前事务 ID"
    }
  },
  visibility: {
    rules: [
      "数据版本的事务 ID < min_trx_id：可见",
      "数据版本的事务 ID = creator_trx_id：可见",
      "数据版本的事务 ID 在 m_ids 中：不可见",
      "数据版本的事务 ID > max_trx_id：不可见"
    ]
  },
  undoLog: {
    role: "存储数据的历史版本",
    chain: "通过回滚指针构建版本链"
  }
}
```

## 📚 锁机制

### 锁类型

```js

const lockTypes = {

    name: "排他锁（X 锁）",

  }
}
```

```sql
-- 使用 EXPLAIN 分析查询

    o.id,
    o.order_no,
    u.username,
    o.total_amount
FROM orders o
LEFT JOIN users u ON o.user_id = u.id
WHERE o.status = 'pending'
AND o.created_at >= '2025-01-01'
ORDER BY o.created_at DESC
```
