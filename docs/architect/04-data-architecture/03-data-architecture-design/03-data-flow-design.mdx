## 📚 ETL vs ELT

### ETL（Extract-Transform-Load）

```js
// ETL 流程
const etlProcess = {
  extract: {
    description: "从源系统提取数据",
    methods: [
      "数据库查询",
      "API 调用",
      "文件读取",
      "日志采集"
    ]
  },
  transform: {
    description: "在中间层转换数据",
    operations: [
      "数据清洗",
      "格式转换",
      "数据聚合",
      "数据验证"
    ],
    location: "独立的服务器或 ETL 工具"
  },
  load: {
    description: "加载到目标系统",
    targets: [
      "数据仓库",
      "数据集市",
      "分析数据库"
    ]
  },
  advantages: [
    "数据质量高",
    "减轻目标系统压力",
    "适合复杂转换逻辑"
  ],
  disadvantages: [
    "处理速度慢",
    "需要额外的转换层",
    "资源消耗大"
  ]
}
```

### ELT（Extract-Load-Transform）

```js
// ELT 流程
const eltProcess = {
  extract: {
    description: "从源系统提取数据",
    methods: ["与 ETL 相同"]
  },
  load: {
    description: "先加载到目标系统",
    targets: ["云数据仓库（如 Snowflake、BigQuery）"]
  },
  transform: {
    description: "在目标系统内转换数据",
    operations: ["使用目标系统的计算能力"],
    location: "目标系统内部"
  },
  advantages: [
    "处理速度快",
    "利用目标系统的计算能力",
    "成本更低",
    "保留原始数据"
  ],
  disadvantages: [
    "依赖目标系统性能",
    "数据质量需要额外保证"
  ]
}
```

### ETL vs ELT 对比

| 特性 | ETL | ELT |
|------|-----|-----|
| 转换位置 | 中间层 | 目标系统 |
| 处理速度 | 慢 | 快 |
| 数据质量 | 高 | 需要额外保证 |
| 成本 | 高 | 低 |
| 适用场景 | 传统数仓 | 云数据仓库 |
| 复杂转换 | 适合 | 受限 |

### Kappa 架构

```js
// Kappa 架构
const kappaArchitecture = {
  description: "简化的流处理架构",
  features: [
    "只有流处理层",
    "通过重放历史数据实现批处理",
    "代码统一"
  ],
  workflow: [
    "所有数据通过消息队列",
    "流处理引擎实时处理",
    "需要批处理时重放消息队列"
  ],
  advantages: [
    "架构简单",
    "代码统一",
    "维护成本低"
  ],
  disadvantages: [
    "依赖消息队列的保留能力",
    "重放历史数据成本高"
  ]
}
```

## 📚 CDC（Change Data Capture）

### CDC 实现方案

```js
// CDC 实现方式
const cdcMethods = {
  timestampBased: {
    description: "基于时间戳",
    method: "查询 updated_at > last_sync_time 的记录",
    advantages: ["实现简单"],
    disadvantages: ["无法捕获删除", "需要额外字段"]
  },
  triggerBased: {
    description: "基于触发器",
    method: "在数据库触发器中捕获变更",
    advantages: ["实时性好"],
    disadvantages: ["影响数据库性能", "维护复杂"]
  },
  logBased: {
    description: "基于日志",
    method: "读取数据库的事务日志（Binlog/WAL）",
    advantages: [
      "实时性好",
      "不影响数据库性能",
      "能捕获所有变更（包括删除）"
    ],
    disadvantages: ["实现复杂"],
    tools: ["Debezium", "Canal", "Maxwell"]
  }
}
```
