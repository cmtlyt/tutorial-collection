## 🔑 核心概念

### 什么是类型系统

类型系统是一组规则，用于：
- **分类值**：将值归类到不同的类型（如整数、字符串、对象）
- **约束操作**：定义哪些操作可以对哪些类型的值执行
- **防止错误**：在编译期或运行期捕获类型不匹配的错误
- **提供抽象**：通过类型系统实现数据抽象和封装

```
类型系统的三个维度：

┌─────────────────────────────────────────┐
│ 维度1：类型检查时机                      │
│  - 静态类型（Static Typing）             │
│    类型检查在编译期进行                  │
│    示例：Java、C++、Rust、TypeScript     │
│                                         │
│  - 动态类型（Dynamic Typing）            │
│    类型检查在运行期进行                  │
│    示例：JavaScript、Python、Ruby        │
├─────────────────────────────────────────┤
│ 维度2：类型表达式强度                    │
│  - 强类型（Strong Typing）               │
│    严格的类型转换规则，隐式转换受限      │
│    示例：Python、Rust、Haskell           │
│                                         │
│  - 弱类型（Weak Typing）                 │
│    允许隐式类型转换，类型边界模糊        │
│    示例：JavaScript、C、PHP              │
├─────────────────────────────────────────┤
│ 维度3：类型显式性                        │
│  - 显式类型（Explicit Typing）           │
│    需要显式声明类型                      │
│    示例：Java、C++、Go                   │
│                                         │
│  - 隐式类型（Implicit Typing）           │
│    类型可以推导或推断                    │
│    示例：TypeScript、Scala、Haskell      │
└─────────────────────────────────────────┘
```

### 类型系统的理论价值

类型系统不仅仅是错误检测工具，它还是：

1. **文档形式**：类型签名本身就是最好的文档
2. **重构保障**：类型系统保证重构不会破坏现有代码
3. **抽象工具**：通过类型实现模块化和封装
4. **性能优化**：静态类型信息可用于编译器优化

### 类型表达式强度

#### 强类型 vs 弱类型

```js
// 弱类型示例：JavaScript
let num = 42;
let str = "10";

// 隐式类型转换 - 弱类型的典型特征
console.log(num + str);  // "4210" - 数字和字符串相加变成字符串拼接
console.log(num - str);  // 32 - 减法操作触发字符串到数字的转换
console.log(num * str);  // 420 - 乘法操作触发字符串到数字的转换
console.log(num == str); // false - 宽松相等会进行类型转换
console.log(num === str);// true - 严格相等不进行类型转换

// 更极端的弱类型行为
console.log(1 + "2" + "2");    // "122"
console.log(1 + +"2" + "2");   // "32"
console.log(1 + -"1" + "2");   // "02"
console.log(+"1" + -"1" + "2"); // "02"
console.log("A" - "B");        // NaN
console.log("A" - "B" + 2);    // NaN
console.log("A" + "B" + 2);    // "AB2"
```

```python
# 强类型示例：Python
num = 42
str_val = "10"

# 严格的类型检查 - 不会隐式转换
# print(num + str_val)  # TypeError: unsupported operand type(s)

# 必须显式转换
print(num + int(str_val))  # 52
print(str(num) + str_val)  # "4210"

# 类型不会被自动改变
x = [1, 2, 3]
# x + "hello"  # TypeError
x + [4, 5]  # [1, 2, 3, 4, 5] - 列表只能和列表相加
```

## 🧬 类型理论核心概念

### 类型推导与类型推断

类型推导（Type Derivation）和类型推断（Type Inference）是类型系统的两个重要概念：

```
类型推导（Type Derivation）：
  - 从表达式推导出其类型
  - 基于类型规则进行形式化推导
  - 用于证明类型系统的正确性

类型推断（Type Inference）：
  - 自动推断表达式的类型，无需显式注解
  - 基于算法（如 Hindley-Milner）实现
  - 提升开发体验，减少样板代码
```

#### Hindley-Milner 类型推断算法

Hindley-Milner 是一种经典的类型推断算法，广泛应用于 ML 家族语言：

```js
// 类型推断示例（TypeScript）

// 无需显式类型注解，编译器可以推断出类型
const add = (a, b) => a + b;
// 推断结果：(a: number, b: number) => number

const identity = (x) => x;
// 推断结果：<T>(x: T) => T （泛型函数）

const map = (fn, arr) => arr.map(fn);
// 推断结果：<T, U>(fn: (x: T) => U, arr: T[]) => U[]

// 复杂的类型推断
const compose = (f, g) => (x) => f(g(x));
// 推断结果：<A, B, C>(f: (b: B) => C, g: (a: A) => B) => (a: A) => C

// 使用推断的类型
const increment = (x) => x + 1;
const double = (x) => x * 2;
const incrementThenDouble = compose(double, increment);

console.log(incrementThenDouble(5)); // 12
// 类型检查：5 是 number → increment 返回 number → double 返回 number
```

### 类型多态性

类型多态性允许同一代码处理不同类型的数据：

```
多态性的三种形式：

┌─────────────────────────────────────┐
│ 1. 参数多态（Parametric Polymorphism）│
│    - 通过类型参数实现                │
│    - 也称为泛型编程                  │
│    - 示例：List<T>、Map<K, V>        │
├─────────────────────────────────────┤
│ 2. 特设多态（Ad-hoc Polymorphism）   │
│    - 通过函数重载实现                │
│    - 同一函数名对不同类型有不同实现   │
│    - 示例：运算符重载、类型类        │
├─────────────────────────────────────┤
│ 3. 子类型多态（Subtype Polymorphism）│
│    - 通过继承/子类型关系实现         │
│    - 父类型引用可以指向子类型对象    │
│    - 示例：Animal animal = new Dog() │
└─────────────────────────────────────┘
```

#### 参数多态（泛型）

#### 特设多态（类型类）

```haskell
-- Haskell 中的类型类示例
class Eq a where
  (==) :: a -> a -> Bool
  (/=) :: a -> a -> Bool

-- 为不同类型实现 Eq
instance Eq Bool where
  True  == True  = True
  False == False = True
  _     == _     = False

instance Eq Int where
  x == y = x == y  -- 使用内置的整数相等

-- 使用类型类约束的函数
elem :: Eq a => a -> [a] -> Bool
elem _ []     = False
elem x (y:ys) = x == y || elem x ys

-- 同一个函数可以用于任何实现了 Eq 的类型
elem 5 [1, 2, 3, 4, 5]      -- True
elem "hello" ["hi", "hello"] -- True
```

### 类型代数

类型代数用代数运算来描述和组合类型：

```
基本类型运算：

1. 和类型（Sum Type / Tagged Union）
   表示"或"关系：值可以是 A 或 B
   记作：A + B
   示例：Result<T, E> = Success(T) | Error(E)

2. 积类型（Product Type）
   表示"且"关系：值同时包含 A 和 B
   记作：A × B
   示例：Pair<A, B> = { first: A, second: B }

3. 函数类型（Function Type）
   表示从 A 到 B 的映射
   记作：A → B
   示例：(x: number) => string

4. 泛型类型（Generic Type）
   表示类型的类型构造器
   记作：F<T>
   示例：List<T>, Option<T>
```

#### 和类型

```typescript
// 和类型示例：表示"或"关系

// 传统方式（不够类型安全）
type Status = "success" | "error" | "loading";
interface ApiResponse {
  status: Status;
  data?: any;
  error?: string;
}

// 和类型方式（类型安全）
type ApiResponse<T> =
  | { status: "success"; data: T }
  | { status: "error"; error: string }
  | { status: "loading" };

// 使用和类型
function handleResponse<T>(response: ApiResponse<T>) {
  switch (response.status) {
    case "success":
      console.log("Data:", response.data); // TypeScript 知道这里有 data
      break;
    case "error":
      console.log("Error:", response.error); // TypeScript 知道这里有 error
      break;
    case "loading":
      console.log("Loading...");
      break;
  }
}

// 编译期保证所有情况都被处理
function processResponse<T>(response: ApiResponse<T>): string {
  if (response.status === "success") {
    return `Success: ${JSON.stringify(response.data)}`;
  } else if (response.status === "error") {
    return `Error: ${response.error}`;
  } else {
    // TypeScript 确保这里只剩下 loading 的情况
    return "Loading...";
  }
}

// 更复杂的和类型：Option/Maybe 类型
type Option<T> =
  | { tag: "some"; value: T }
  | { tag: "none" };

function divide(a: number, b: number): Option<number> {
  if (b === 0) {
    return { tag: "none" };
  }
  return { tag: "some", value: a / b };
}

function mapOption<T, U>(
  opt: Option<T>,
  fn: (value: T) => U
): Option<U> {
  if (opt.tag === "some") {
    return { tag: "some", value: fn(opt.value) };
  }
  return { tag: "none" };
}

// 链式操作
const result = mapOption(
  divide(10, 2),
  (x) => x * 2
); // { tag: "some", value: 10 }
```

## 🏗️ 渐进式类型系统

渐进式类型系统结合了静态类型和动态类型的优点：

```
渐进式类型系统的特点：

┌─────────────────────────────────────────┐
│ 核心思想：                               │
│ 允许部分代码有类型注解，部分代码没有     │
│ 有类型的部分进行静态检查                 │
│ 没有类型的部分进行动态检查               │
│ 两者可以无缝互操作                       │
├─────────────────────────────────────────┤
│ 典型代表：                               │
│ - TypeScript                            │
│ - Flow                                  │
│ - Python (type hints + mypy)            │
│ - PHP (type declarations)               │
├─────────────────────────────────────────┤
│ 架构意义：                               │
│ 可以逐步将现有项目迁移到类型系统         │
│ 核心业务逻辑使用严格类型                 │
│ 快速原型或第三方集成使用动态类型         │
└─────────────────────────────────────────┘
```

```typescript
// TypeScript 渐进式类型示例

// 完全类型化的代码
interface User {
  id: string;
  name: string;
  email: string;
}

function sendEmail(user: User, message: string): void {
  console.log(`Sending to ${user.email}: ${message}`);
}

// 渐进式：混合使用类型化和动态代码
function processUserData(data: any): User {
  // 动态访问属性
  if (data.user && data.user.id) {
    return {
      id: data.user.id,
      name: data.user.name || "Unknown",
      email: data.user.email,
    };
  }
  throw new Error("Invalid user data");
}

// 类型断言：告诉编译器"我知道我在做什么"
const rawResponse: any = fetchUserData();
const user = rawResponse as User;

// 类型守卫：运行时类型检查
function isUser(obj: any): obj is User {
  return (
    typeof obj === "object" &&
    typeof obj.id === "string" &&
    typeof obj.name === "string" &&
    typeof obj.email === "string"
  );
}

if (isUser(rawResponse)) {
  sendEmail(rawResponse, "Welcome!");
}
```

## 🎯 类型系统在架构中的应用

### 类型驱动的架构设计

类型系统可以指导架构设计决策：

```
类型驱动的架构设计原则：

1. 类型即文档
   - API 接口通过类型定义
   - 数据结构通过类型约束
   - 业务规则通过类型表达

2. 类型即测试
   - 编译期类型检查相当于单元测试
   - 类型系统保证不变量不被破坏
   - 减少运行时错误

3. 类型即约束
   - 通过类型限制非法状态
   - 使非法状态不可表示
   - 编译期验证业务规则
```

#### 领域建模与类型系统

```typescript
// 使用类型系统表达业务规则

// ❌ 原始类型 - 不够类型安全
type UserId = string;
type Email = string;
type Money = number;

function transferMoney(
  fromUserId: UserId,
  toUserId: UserId,
  amount: Money
): void {
  // 容易出错：amount 可能是负数
  // fromUserId 和 toUserId 可能相同
}

// ✅ 使用类型系统增强安全性

// 使用品牌类型（Branded Types）
type UserId = string & { readonly __brand: unique symbol };
type Email = string & { readonly __brand: unique symbol };

// 使用 newtype 模式封装金额，确保非负
class Money {
  private constructor(private readonly value: number) {}

  static of(value: number): Money {
    if (value < 0) {
      throw new Error("Money cannot be negative");
    }
    return new Money(value);
  }

  add(other: Money): Money {
    return new Money(this.value + other.value);
  }

  subtract(other: Money): Money {
    const result = this.value - other.value;
    if (result < 0) {
      throw new Error("Insufficient funds");
    }
    return new Money(result);
  }

  getValue(): number {
    return this.value;
  }
}

// 使用和类型表达账户状态
type AccountStatus =
  | { status: "active" }
  | { status: "frozen"; reason: string }
  | { status: "closed" };

interface Account {
  id: UserId;
  email: Email;
  balance: Money;
  status: AccountStatus;
}

// 类型安全的转账
function transferMoney(
  fromAccount: Account,
  toAccount: Account,
  amount: Money
): void {
  // 编译期检查：确保账户状态有效
  if (fromAccount.status.status !== "active") {
    throw new Error(`Source account is ${fromAccount.status.status}`);
  }

  if (toAccount.status.status !== "active") {
    throw new Error(`Destination account is ${toAccount.status.status}`);
  }

  // 运行时检查：确保余额充足
  fromAccount.balance = fromAccount.balance.subtract(amount);
  toAccount.balance = toAccount.balance.add(amount);
}

// 创建账户
const account1: Account = {
  id: "user-001" as UserId,
  email: "alice@example.com" as Email,
  balance: Money.of(1000),
  status: { status: "active" },
};

const account2: Account = {
  id: "user-002" as UserId,
  email: "bob@example.com" as Email,
  balance: Money.of(500),
  status: { status: "active" },
};

// 执行转账
transferMoney(account1, account2, Money.of(200));
console.log(account1.balance.getValue()); // 800
console.log(account2.balance.getValue()); // 700
```

```typescript
// TypeScript 会检查请求和响应的类型
const response = await client.post("POST /users", {
  name: "Alice",
  email: "alice@example.com",
  password: "secret123",
});

if (response.success) {
  console.log(response.data.name); // TypeScript 知道这里有 data
}
```

## 📊 类型系统对比

| 特性 | 静态类型 | 动态类型 | 渐进式类型 |
|------|---------|---------|-----------|
| **错误检测时机** | 编译期 | 运行期 | 混合 |
| **开发速度** | 较慢 | 较快 | 中等 |
| **运行时性能** | 更好 | 较差 | 中等 |
| **代码可维护性** | 高 | 中等 | 高 |
| **学习曲线** | 陡峭 | 平缓 | 中等 |
| **灵活性** | 低 | 高 | 高 |
| **IDE 支持** | 优秀 | 一般 | 优秀 |
| **重构安全性** | 高 | 低 | 高 |
| **典型语言** | Java, Rust, Go | Python, Ruby, JS | TypeScript, Flow |
