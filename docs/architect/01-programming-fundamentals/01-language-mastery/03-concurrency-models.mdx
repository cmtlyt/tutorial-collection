## 🧵 线程模型

### 什么是线程

线程是操作系统调度的基本单位，一个进程可以包含多个线程，它们共享进程的内存空间和资源：

```
进程
┌─────────────────────────────────────┐
│  共享资源                            │
│  ┌─────────────────────────────┐    │
│  │ 堆内存、全局变量、文件描述符   │    │
│  └─────────────────────────────┘    │
│                                     │
│  线程1        线程2        线程3     │
│  ┌──────┐   ┌──────┐   ┌──────┐    │
│  │ 栈   │   │ 栈   │   │ 栈   │    │
│  │ PC   │   │ PC   │   │ PC   │    │
│  │ 寄存器│   │ 寄存器│   │ 寄存器│    │
│  └──────┘   └──────┘   └──────┘    │
└─────────────────────────────────────┘
```

### 线程同步机制

多线程共享内存意味着需要同步机制来避免竞态条件。常见的同步原语包括：

**互斥锁（Mutex）**：保证同一时刻只有一个线程访问临界区

```js
// 模拟互斥锁的概念
class Mutex {
  constructor() {
    this.locked = false;
    this.waitQueue = [];
  }

  async acquire() {
    while (this.locked) {
      await new Promise((resolve) => this.waitQueue.push(resolve));
    }
    this.locked = true;
  }

  release() {
    this.locked = false;
    const nextWaiter = this.waitQueue.shift();
    if (nextWaiter) {
      nextWaiter();
    }
  }
}

// 使用互斥锁保护共享资源
const mutex = new Mutex();
let sharedCounter = 0;

async function incrementCounter(threadId, times) {
  for (let i = 0; i < times; i++) {
    await mutex.acquire();
    sharedCounter++;
    console.log(`Thread ${threadId}: counter = ${sharedCounter}`);
    mutex.release();
  }
}

async function main() {
  await Promise.all([
    incrementCounter("A", 3),
    incrementCounter("B", 3),
  ]);
  console.log(`Final counter: ${sharedCounter}`);
}

main();
// Thread A: counter = 1
// Thread A: counter = 2
// Thread A: counter = 3
// Thread B: counter = 4
// Thread B: counter = 5
// Thread B: counter = 6
// Final counter: 6
```

**读写锁（ReadWrite Lock）**：允许多个读操作并发，但写操作互斥

```js
class ReadWriteLock {
  constructor() {
    this.readers = 0;
    this.writer = false;
    this.readWaiters = [];
    this.writeWaiters = [];
  }

  async acquireRead() {
    while (this.writer) {
      await new Promise((resolve) => this.readWaiters.push(resolve));
    }
    this.readers++;
  }

  releaseRead() {
    this.readers--;
    if (this.readers === 0 && this.writeWaiters.length > 0) {
      this.writeWaiters.shift()();
    }
  }

  async acquireWrite() {
    while (this.writer || this.readers > 0) {
      await new Promise((resolve) => this.writeWaiters.push(resolve));
    }
    this.writer = true;
  }

  releaseWrite() {
    this.writer = false;
    // 优先唤醒所有等待的读者
    while (this.readWaiters.length > 0) {
      this.readWaiters.shift()();
    }
    // 如果没有等待的读者，唤醒一个写者
    if (this.writeWaiters.length > 0) {
      this.writeWaiters.shift()();
    }
  }
}

const rwLock = new ReadWriteLock();
const cache = new Map();

async function readFromCache(key) {
  await rwLock.acquireRead();
  const value = cache.get(key);
  console.log(`Read: ${key} = ${value}`);
  rwLock.releaseRead();
  return value;
}

async function writeToCache(key, value) {
  await rwLock.acquireWrite();
  cache.set(key, value);
  console.log(`Write: ${key} = ${value}`);
  rwLock.releaseWrite();
}

async function main() {
  await writeToCache("name", "Alice");
  await Promise.all([
    readFromCache("name"),
    readFromCache("name"),
    readFromCache("name"),
  ]);
}

main();
// Write: name = Alice
// Read: name = Alice
// Read: name = Alice
// Read: name = Alice
```

### 线程池模式

在实际应用中，频繁创建和销毁线程开销很大，因此通常使用线程池：

```js
class ThreadPool {
  constructor(maxWorkers) {
    this.maxWorkers = maxWorkers;
    this.activeWorkers = 0;
    this.taskQueue = [];
  }

  submit(task) {
    return new Promise((resolve, reject) => {
      const wrappedTask = async () => {
        try {
          const result = await task();
          resolve(result);
        } catch (error) {
          reject(error);
        } finally {
          this.activeWorkers--;
          this.processQueue();
        }
      };

      if (this.activeWorkers < this.maxWorkers) {
        this.activeWorkers++;
        wrappedTask();
      } else {
        this.taskQueue.push(wrappedTask);
      }
    });
  }

  processQueue() {
    if (this.taskQueue.length > 0 && this.activeWorkers < this.maxWorkers) {
      this.activeWorkers++;
      const nextTask = this.taskQueue.shift();
      nextTask();
    }
  }
}

// 使用线程池处理批量任务
const pool = new ThreadPool(3);

function createTask(taskId, durationMs) {
  return async () => {
    console.log(`Task ${taskId} started (active: ${pool.activeWorkers})`);
    await new Promise((resolve) => setTimeout(resolve, durationMs));
    console.log(`Task ${taskId} completed`);
    return `Result of task ${taskId}`;
  };
}

async function main() {
  const tasks = [];
  for (let i = 1; i <= 6; i++) {
    tasks.push(pool.submit(createTask(i, 100)));
  }
  const results = await Promise.all(tasks);
  console.log("All results:", results);
}

main();
// 最多同时运行 3 个任务，其余在队列中排队
```

### 线程模型的挑战

```
常见问题：
┌──────────────────────────────────────┐
│ 死锁 (Deadlock)                      │
│ - 线程A持有锁1，等待锁2              │
│ - 线程B持有锁2，等待锁1              │
│ - 两者互相等待，永远无法继续          │
├──────────────────────────────────────┤
│ 竞态条件 (Race Condition)            │
│ - 多线程对共享数据的非原子操作        │
│ - 结果依赖于线程执行的时序            │
├──────────────────────────────────────┤
│ 活锁 (Livelock)                      │
│ - 线程不断改变状态但无法推进          │
│ - 类比两人在走廊相向而行不断让路      │
├──────────────────────────────────────┤
│ 优先级反转 (Priority Inversion)      │
│ - 低优先级线程持有高优先级线程需要的锁│
│ - 导致高优先级线程被阻塞             │
└──────────────────────────────────────┘
```

## 🔄 协程模型

### 什么是协程

协程（Coroutine）是用户态的轻量级线程，由运行时或语言层面调度，而非操作系统内核调度。相比操作系统线程，协程具有更小的内存开销和更快的切换速度。

```
对比：
┌─────────────────────────────────────────┐
│ 操作系统线程                             │
│ - 栈大小：1MB（默认）                    │
│ - 创建开销：数十微秒                      │
│ - 上下文切换：数微秒（内核态切换）         │
│ - 数量限制：通常数千个                    │
│ - 调度方式：操作系统内核抢占式调度         │
├─────────────────────────────────────────┤
│ 协程                                     │
│ - 栈大小：2KB-8KB（可动态增长）           │
│ - 创建开销：数百纳秒                      │
│ - 上下文切换：数十纳秒（用户态切换）       │
│ - 数量限制：轻松百万级                    │
│ - 调度方式：运行时协作式/抢占式调度        │
└─────────────────────────────────────────┘
```

### Go 的 Goroutine

Go 的 Goroutine 是协程的典型实现，配合 Channel 进行通信：

```
CSP (Communicating Sequential Processes) 模型：
  "不要通过共享内存来通信，而是通过通信来共享内存"

  Goroutine A ──→ Channel ──→ Goroutine B
  （发送数据）    （管道）     （接收数据）
```

### JavaScript 的异步模型

JavaScript 采用单线程事件循环 + 异步回调的模型，async/await 本质上也是协程的一种实现：

```js
// JavaScript 的事件循环模型
// 单线程 + 非阻塞 I/O + 事件循环

// 模拟事件循环的工作方式
class EventLoop {
  constructor() {
    this.macroTaskQueue = [];
    this.microTaskQueue = [];
  }

  addMacroTask(task, label) {
    this.macroTaskQueue.push({ task, label });
  }

  addMicroTask(task, label) {
    this.microTaskQueue.push({ task, label });
  }

  run() {
    console.log("=== Event Loop Start ===");

    // 执行所有微任务（优先于宏任务）
    while (this.microTaskQueue.length > 0) {
      const { task, label } = this.microTaskQueue.shift();
      console.log(`[MicroTask] ${label}`);
      task();
    }

    // 执行一个宏任务
    if (this.macroTaskQueue.length > 0) {
      const { task, label } = this.macroTaskQueue.shift();
      console.log(`[MacroTask] ${label}`);
      task();

      // 宏任务执行完后，再次清空微任务队列
      while (this.microTaskQueue.length > 0) {
        const { task: microTask, label: microLabel } = this.microTaskQueue.shift();
        console.log(`[MicroTask] ${microLabel}`);
        microTask();
      }
    }

    console.log("=== Event Loop Tick End ===");
  }
}

const loop = new EventLoop();
loop.addMacroTask(() => console.log("  setTimeout callback"), "setTimeout");
loop.addMicroTask(() => console.log("  Promise.then callback"), "Promise.then");
loop.addMicroTask(() => console.log("  queueMicrotask callback"), "queueMicrotask");
loop.run();
// === Event Loop Start ===
// [MicroTask] Promise.then
//   Promise.then callback
// [MicroTask] queueMicrotask
//   queueMicrotask callback
// [MacroTask] setTimeout
//   setTimeout callback
// === Event Loop Tick End ===
```

### async/await 与协程的关系

```js
// async/await 本质上是协程的语法糖
// 编译器会将 async 函数转换为状态机

// 原始 async/await 代码
async function fetchUserData(userId) {
  const response = await fetch(`/api/users/${userId}`);
  const user = await response.json();
  return user;
}

// 概念上等价于以下状态机
function fetchUserDataStateMachine(userId) {
  let state = 0;
  let response;
  let user;

  function resume(value) {
    switch (state) {
      case 0:
        state = 1;
        return fetch(`/api/users/${userId}`).then(resume);
      case 1:
        response = value;
        state = 2;
        return response.json().then(resume);
      case 2:
        user = value;
        return Promise.resolve(user);
    }
  }

  return resume();
}

// 两者的执行效果完全一致
// async/await 只是让异步代码看起来像同步代码
```

### 协程的典型应用场景

```js
// 场景1：并发网络请求（扇出模式）
async function fetchMultipleAPIs() {
  const urls = [
    "https://api.example.com/users",
    "https://api.example.com/orders",
    "https://api.example.com/products",
  ];

  // 所有请求并发执行
  const startTime = Date.now();
  const results = await Promise.all(
    urls.map(async (url) => {
      const response = await fetch(url);
      return response.json();
    })
  );

  console.log(`All fetched in ${Date.now() - startTime}ms`);
  return results;
}

// 场景2：带并发限制的批量处理
async function processWithConcurrencyLimit(items, concurrency, processor) {
  const results = [];
  const executing = new Set();

  for (const item of items) {
    const promise = processor(item).then((result) => {
      executing.delete(promise);
      return result;
    });
    executing.add(promise);
    results.push(promise);

    if (executing.size >= concurrency) {
      await Promise.race(executing);
    }
  }

  return Promise.all(results);
}

// 最多同时处理 5 个任务
async function main() {
  const items = Array.from({ length: 20 }, (_, i) => i + 1);
  const results = await processWithConcurrencyLimit(
    items,
    5,
    async (item) => {
      await new Promise((resolve) => setTimeout(resolve, Math.random() * 100));
      console.log(`Processed item ${item}`);
      return item * 2;
    }
  );
  console.log("Results:", results);
}

main();
```

## 🎭 Actor 模型

### 什么是 Actor 模型

Actor 模型是一种并发计算模型，每个 Actor 是独立的计算单元，通过消息传递进行通信，不共享任何状态：

```
Actor 模型核心概念：

每个 Actor 具备三种能力：
1. 发送消息给其他 Actor
2. 创建新的 Actor
3. 指定收到下一条消息时的行为

┌──────────┐    消息    ┌──────────┐
│  Actor A │ ────────→ │  Actor B │
│          │           │          │
│ 私有状态  │    消息    │ 私有状态  │
│ 邮箱     │ ←──────── │ 邮箱     │
└──────────┘           └──────────┘
     │                      │
     │ 创建                  │ 创建
     ↓                      ↓
┌──────────┐           ┌──────────┐
│  Actor C │           │  Actor D │
└──────────┘           └──────────┘

关键特性：
- 每个 Actor 有自己的私有状态（不可被外部直接访问）
- 通信只通过异步消息传递（没有共享内存）
- 每个 Actor 有一个邮箱（消息队列），按序处理消息
- Actor 一次只处理一条消息（天然避免竞态条件）
```

### JavaScript 中的 Actor 模式实现

```js
// 用 JavaScript 实现一个简单的 Actor 系统
class Actor {
  constructor(name, behavior) {
    this.name = name;
    this.mailbox = [];
    this.processing = false;
    this.behavior = behavior;
    this.state = {};
  }

  send(message) {
    this.mailbox.push(message);
    if (!this.processing) {
      this.processNextMessage();
    }
  }

  async processNextMessage() {
    if (this.mailbox.length === 0) {
      this.processing = false;
      return;
    }

    this.processing = true;
    const message = this.mailbox.shift();
    console.log(`[${this.name}] Processing: ${JSON.stringify(message)}`);

    await this.behavior(this, message);
    this.processNextMessage();
  }
}

class ActorSystem {
  constructor() {
    this.actors = new Map();
  }

  createActor(name, behavior) {
    const actor = new Actor(name, behavior);
    this.actors.set(name, actor);
    return actor;
  }

  send(actorName, message) {
    const actor = this.actors.get(actorName);
    if (actor) {
      actor.send(message);
    } else {
      console.error(`Actor "${actorName}" not found`);
    }
  }
}

// 使用 Actor 模型实现一个银行转账系统
const system = new ActorSystem();

// 账户 Actor：管理自己的余额
function accountBehavior(actor, message) {
  switch (message.type) {
    case "init":
      actor.state.balance = message.balance;
      console.log(`  [${actor.name}] Balance initialized: ${actor.state.balance}`);
      break;

    case "deposit":
      actor.state.balance += message.amount;
      console.log(`  [${actor.name}] Deposited ${message.amount}, balance: ${actor.state.balance}`);
      if (message.replyTo) {
        system.send(message.replyTo, {
          type: "deposit-confirmed",
          account: actor.name,
          amount: message.amount,
        });
      }
      break;

    case "withdraw":
      if (actor.state.balance >= message.amount) {
        actor.state.balance -= message.amount;
        console.log(`  [${actor.name}] Withdrew ${message.amount}, balance: ${actor.state.balance}`);
        if (message.replyTo) {
          system.send(message.replyTo, {
            type: "withdraw-confirmed",
            account: actor.name,
            amount: message.amount,
          });
        }
      } else {
        console.log(`  [${actor.name}] Insufficient funds`);
        if (message.replyTo) {
          system.send(message.replyTo, {
            type: "withdraw-failed",
            account: actor.name,
            reason: "insufficient-funds",
          });
        }
      }
      break;

    case "get-balance":
      console.log(`  [${actor.name}] Current balance: ${actor.state.balance}`);
      break;
  }
}

// 转账协调器 Actor
function transferCoordinatorBehavior(actor, message) {
  switch (message.type) {
    case "transfer":
      console.log(`  [Coordinator] Transfer ${message.amount} from ${message.from} to ${message.to}`);
      system.send(message.from, {
        type: "withdraw",
        amount: message.amount,
        replyTo: actor.name,
      });
      actor.state.pendingTransfer = {
        to: message.to,
        amount: message.amount,
      };
      break;

    case "withdraw-confirmed":
      const pending = actor.state.pendingTransfer;
      system.send(pending.to, {
        type: "deposit",
        amount: pending.amount,
        replyTo: actor.name,
      });
      break;

    case "deposit-confirmed":
      console.log(`  [Coordinator] Transfer completed successfully`);
      break;

    case "withdraw-failed":
      console.log(`  [Coordinator] Transfer failed: ${message.reason}`);
      break;
  }
}

// 创建 Actor 并执行转账
system.createActor("accountAlice", accountBehavior);
system.createActor("accountBob", accountBehavior);
system.createActor("coordinator", transferCoordinatorBehavior);

system.send("accountAlice", { type: "init", balance: 1000 });
system.send("accountBob", { type: "init", balance: 500 });
system.send("coordinator", {
  type: "transfer",
  from: "accountAlice",
  to: "accountBob",
  amount: 200,
});
// [accountAlice] Processing: {"type":"init","balance":1000}
//   [accountAlice] Balance initialized: 1000
// [accountBob] Processing: {"type":"init","balance":500}
//   [accountBob] Balance initialized: 500
// [coordinator] Processing: {"type":"transfer","from":"accountAlice","to":"accountBob","amount":200}
//   [Coordinator] Transfer 200 from accountAlice to accountBob
// [accountAlice] Processing: {"type":"withdraw","amount":200,"replyTo":"coordinator"}
//   [accountAlice] Withdrew 200, balance: 800
// [coordinator] Processing: {"type":"withdraw-confirmed",...}
// [accountBob] Processing: {"type":"deposit","amount":200,...}
//   [accountBob] Deposited 200, balance: 700
// [coordinator] Processing: {"type":"deposit-confirmed",...}
//   [Coordinator] Transfer completed successfully
```

## 📊 三种并发模型对比

| 维度 | 线程模型 | 协程模型 | Actor 模型 |
|------|---------|---------|-----------|
| **通信方式** | 共享内存 + 锁 | 共享内存 / Channel | 消息传递 |
| **调度方式** | 操作系统内核 | 运行时/语言层面 | Actor 运行时 |
| **内存开销** | 大（~1MB/线程） | 小（~2KB/协程） | 中等 |
| **并发规模** | 数千级 | 百万级 | 百万级 |
| **编程难度** | 高（需管理锁） | 中等 | 低（无锁） |
| **适用场景** | CPU 密集型 | I/O 密集型 | 分布式系统 |
| **典型实现** | Java Thread, POSIX | Go Goroutine, JS async | Erlang/Elixir, Akka |
| **错误传播** | 异常可能影响整个进程 | 异常局部化 | 故障隔离（Let it crash） |

## 📝 实际应用：选择合适的并发模型

```js
// 并发模型选择决策框架
function recommendConcurrencyModel(scenario) {
  const { workloadType, concurrencyScale, faultTolerance, teamExperience } = scenario;

  const recommendations = [];

  if (workloadType === "io-intensive") {
    recommendations.push({
      model: "Coroutine (async/await)",
      reason: "I/O 密集型任务，协程可以在等待 I/O 时让出执行权",
      examples: "Web 服务器、API 网关、数据库查询",
    });
  }

  if (workloadType === "cpu-intensive") {
    recommendations.push({
      model: "Thread / Worker Thread",
      reason: "CPU 密集型任务需要真正的并行执行",
      examples: "图像处理、数据分析、密码学计算",
    });
  }

  if (concurrencyScale === "massive" && faultTolerance === "critical") {
    recommendations.push({
      model: "Actor Model",
      reason: "百万级并发 + 高容错要求，Actor 的故障隔离特性最合适",
      examples: "即时通讯、IoT 设备管理、电信系统",
    });
  }

  if (concurrencyScale === "massive" && workloadType === "io-intensive") {
    recommendations.push({
      model: "Goroutine + Channel (CSP)",
      reason: "海量 I/O 并发，Go 的 GMP 调度器高效管理百万协程",
      examples: "微服务、API 聚合层、代理服务",
    });
  }

  return recommendations;
}

// 场景1：电商 Web 服务
const webServiceResult = recommendConcurrencyModel({
  workloadType: "io-intensive",
  concurrencyScale: "high",
  faultTolerance: "moderate",
  teamExperience: "javascript",
});
console.log("Web 服务推荐:", JSON.stringify(webServiceResult, null, 2));

// 场景2：实时聊天系统
const chatSystemResult = recommendConcurrencyModel({
  workloadType: "io-intensive",
  concurrencyScale: "massive",
  faultTolerance: "critical",
  teamExperience: "erlang",
});
console.log("聊天系统推荐:", JSON.stringify(chatSystemResult, null, 2));
```
