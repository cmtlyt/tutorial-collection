## 🔑 核心概念

### DDD 的核心价值

DDD 不仅是一套技术模式，更是一种**将业务复杂度转化为技术架构**的思维方式：

- **战略设计**解决的是"边界在哪里"的问题 → 决定系统如何拆分
- **战术设计**解决的是"内部如何组织"的问题 → 决定代码如何结构化
- **通用语言**解决的是"团队如何沟通"的问题 → 消除业务与技术的鸿沟

### 限界上下文与微服务

限界上下文是微服务拆分的最佳指导原则：

```
业务领域
  ├── 核心子域 → 自研、重点投入
  ├── 支撑子域 → 可外包、适度投入
  └── 通用子域 → 购买/使用开源方案
```
