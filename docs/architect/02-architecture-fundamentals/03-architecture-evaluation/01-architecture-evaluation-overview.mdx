# 架构评估与决策 - 总览

> **版本**：v1.0
> **最后更新**：2026-04-24

## 📚 章节介绍

本章节讲解如何系统性地评估架构方案和做出架构决策，包括质量属性分析、架构评估方法和架构决策记录。

## 🎯 学习目标

完成本章节学习后，你将能够：
- 理解并运用核心质量属性（可用性、可扩展性、安全性等）
- 掌握 ATAM 等架构评估方法
- 能够撰写规范的架构决策记录（ADR）
- 建立系统化的技术选型方法论

## 📖 章节结构

### 第一部分：质量属性
- 可用性（Availability）
- 可扩展性（Scalability）
- 可维护性（Maintainability）
- 安全性（Security）
- 性能（Performance）
- 可测试性（Testability）

### 第二部分：架构评估方法
- ATAM（Architecture Tradeoff Analysis Method）
- 架构适应度函数（Fitness Functions）
- 技术债务评估

### 第三部分：架构决策记录
- ADR（Architecture Decision Records）
- 权衡分析与取舍
- 技术选型方法论

## 🔑 核心概念

### 架构是权衡的艺术

每个架构决策都涉及权衡。例如：
- **一致性 vs 可用性**（CAP 定理）
- **性能 vs 可维护性**（过度优化降低可读性）
- **灵活性 vs 复杂度**（过度抽象增加认知负担）

### ADR 模板

```
# ADR-001: 选择消息队列方案

## 状态：已接受

## 背景
系统需要异步解耦订单和支付模块...

## 决策
选择 Apache Kafka 作为消息队列...

## 后果
- 正面：高吞吐、持久化、可回溯
- 负面：运维复杂度增加、学习成本
```
