## 📚 架构决策制定理论基础

### 架构决策的重要性

#### 什么是架构决策？

架构决策是**对软件系统结构、行为和质量属性具有重大影响的技术选择**。这些决策通常难以逆转，会对系统的长期可维护性、可扩展性和性能产生深远影响。

**理论依据**：
- 架构是设计决策的集合
- 架构决策决定了系统的质量属性
- 错误的架构决策后期修复成本极高

#### 架构决策的特征

| 特征 | 说明 | 示例 |
|------|------|------|
| **长期影响** | 决策影响系统的整个生命周期 | 选择微服务架构影响团队组织和技术栈 |
| **难以逆转** | 一旦实施，回退成本很高 | 从单体迁移到微服务需要大量重构 |
| **权衡性质** | 涉及多个质量属性的权衡 | 选择 NoSQL 牺牲一致性换取性能 |
| **不确定性** | 面对未来变化的预测和假设 | 假设用户量会持续增长选择可扩展架构 |

### 架构决策制定方法论

#### 决策制定的流程

**1. 问题识别**
- 明确需要解决的业务或技术问题
- 识别当前架构的局限性
- 收集相关的约束条件

**2. 目标设定**
- 定义决策的业务目标
- 确定关键质量属性要求
- 设定成功的衡量标准

**3. 方案生成**
- 头脑风暴可能的解决方案
- 研究行业最佳实践
- 评估现有技术的适用性

**4. 方案评估**
- 分析每个方案的优缺点
- 评估对质量属性的影响
- 考虑实施成本和风险

**5. 权衡分析**
- 识别方案之间的权衡关系
- 评估不同质量属性的优先级
- 选择最优的权衡方案

**6. 决策制定**
- 基于分析结果做出选择
- 记录决策理由和依据
- 明确决策的适用范围

**7. 实施和验证**
- 制定实施计划
- 验证决策的有效性
- 监控决策的影响

#### 决策制定的挑战

| 挑战 | 原因 | 应对策略 |
|------|------|---------|
| **信息不完整** | 面对未来的不确定性 | 采用渐进式决策，预留演进空间 |
| **利益冲突** | 不同利益相关者有不同目标 | 建立决策委员会，明确优先级 |
| **技术偏见** | 过度偏好熟悉的技术 | 多方评估，引入外部专家 |
| **时间压力** | 项目进度要求快速决策 | 分阶段决策，关键决策充分论证 |

### 架构决策的分类

#### 按影响范围分类

**1. 战略级决策**
- 影响整个系统的架构方向
- 决定技术栈和架构风格
- 示例：选择微服务架构、选择云平台

**2. 战术级决策**
- 影响特定模块或子系统
- 决定具体的技术实现
- 示例：选择消息队列、选择缓存方案

**3. 操作级决策**
- 影响具体的代码实现
- 决定编码规范和工具
- 示例：选择日志框架、选择测试框架

#### 按决策性质分类

**1. 一次性决策**
- 难以逆转的重大决策
- 需要充分论证
- 示例：架构风格选择、编程语言选择

**2. 可逆决策**
- 可以相对容易地修改
- 可以快速迭代
- 示例：库版本选择、配置参数调整

**3. 暂时性决策**
- 作为过渡方案
- 计划后续替换
- 示例：临时数据迁移方案、快速原型

### 权衡分析理论

#### 权衡的本质

架构决策本质上是**在不同质量属性之间进行权衡**。没有任何架构能够在所有质量属性上都达到最优。

#### 权衡分析的方法

**1. 敏感性分析**

分析架构决策对质量属性的敏感程度：

```
敏感性分析流程：
1. 识别关键架构决策
2. 评估决策变化对质量属性的影响
3. 确定需要重点关注的决策点
```

**2. 权衡点分析**

识别多个质量属性相互影响的架构决策：

```
权衡点分析流程：
1. 分析决策对多个质量属性的影响
2. 评估权衡的合理性
3. 确定最优的权衡方案
```

**3. 风险分析**

评估架构决策带来的风险：

```
风险分析流程：
1. 识别潜在的质量风险
2. 评估风险的影响和概率
3. 制定风险缓解策略
```

#### 权衡决策的原则

**1. 业务优先原则**
- 质量属性优先级由业务需求决定
- 核心业务需求优先于非核心需求
- 用户价值优先于技术理想

**2. 成本效益原则**
- 评估决策的成本和收益
- 选择性价比最高的方案
- 避免过度设计

**3. 可逆性原则**
- 优先选择可逆的决策
- 为不可逆决策提供充分的论证
- 为决策变更预留空间

**4. 渐进式原则**
- 采用渐进式的决策方式
- 通过实践验证决策的有效性
- 根据反馈调整决策

## 📝 ADR（Architecture Decision Records）

### 什么是 ADR？

ADR 是一种轻量级的文档格式，用于**记录重要的架构决策**。每个 ADR 记录一个决策，包括上下文、决策内容、理由和后果。ADR 最早由 Michael Nygard 在 2011 年提出。

### 为什么需要 ADR？

| 问题 | 没有 ADR | 有 ADR |
|------|---------|--------|
| "为什么用 Kafka 不用 RabbitMQ？" | 没人记得当时怎么决定的 | ADR-007 详细记录了选型理由 |
| 新架构师入职 | 需要几个月才能理解历史决策 | 阅读 ADR 库快速了解架构演变 |
| 要不要替换某个组件？ | 缺乏当时的约束信息，盲目决策 | 回顾原始 ADR，评估约束是否已变化 |
| 同样的争论反复出现 | 每次重新讨论一遍 | 指向已有 ADR，终结争论 |

### ADR 的标准格式

```
# ADR-{编号}: {决策标题}

## 状态
{提议 | 已接受 | 已弃用 | 已取代}（被 ADR-XXX 取代）

## 日期
{决策日期}

## 背景
{描述驱动这个决策的业务/技术背景、问题和约束条件}

## 决策
{我们决定采用什么方案，具体怎么做}

## 理由
{为什么选择这个方案而非其他方案}

## 后果
{这个决策会带来的正面和负面影响}

## 备选方案
{列举考虑过但未采纳的方案及原因}
```

### ADR 状态生命周期

```
提议（Proposed）
  ↓ 团队讨论通过
已接受（Accepted）
  ↓ 环境/需求变化
已弃用（Deprecated）或 被取代（Superseded by ADR-XXX）
```

### 代码示例：ADR 管理工具

```js
// ========== ADR 管理工具 ==========

class AdrRecord {
  constructor(id, title, context, decision, rationale, consequences, alternatives) {
    this.id = id;
    this.title = title;
    this.status = 'proposed';
    this.date = new Date().toISOString().split('T')[0];
    this.context = context;
    this.decision = decision;
    this.rationale = rationale;
    this.consequences = consequences;  // { positive: [], negative: [] }
    this.alternatives = alternatives;  // [{ name, reason }]
    this.supersededBy = null;
  }

  accept() {
    this.status = 'accepted';
    this.date = new Date().toISOString().split('T')[0];
  }

  deprecate(reason) {
    this.status = 'deprecated';
    this.deprecatedReason = reason;
  }

  supersede(newAdrId) {
    this.status = 'superseded';
    this.supersededBy = newAdrId;
  }

  toMarkdown() {
    let statusText = this.status;
    if (this.supersededBy) statusText += `（被 ADR-${this.supersededBy} 取代）`;

    let markdown = '';
    markdown += `# ADR-${this.id}: ${this.title}\n\n`;
    markdown += `## 状态\n${statusText}\n\n`;
    markdown += `## 日期\n${this.date}\n\n`;
    markdown += `## 背景\n${this.context}\n\n`;
    markdown += `## 决策\n${this.decision}\n\n`;
    markdown += `## 理由\n${this.rationale}\n\n`;
    markdown += `## 后果\n`;
    markdown += `### 正面\n`;
    for (const item of this.consequences.positive) {
      markdown += `- ${item}\n`;
    }
    markdown += `\n### 负面\n`;
    for (const item of this.consequences.negative) {
      markdown += `- ${item}\n`;
    }
    markdown += `\n## 备选方案\n`;
    for (const alt of this.alternatives) {
      markdown += `- **${alt.name}**: ${alt.reason}\n`;
    }
    return markdown;
  }
}

class AdrRepository {
  constructor(projectName) {
    this.projectName = projectName;
    this.records = new Map();
    this.nextId = 1;
  }

  create(title, context, decision, rationale, consequences, alternatives) {
    const id = String(this.nextId++).padStart(3, '0');
    const adr = new AdrRecord(id, title, context, decision, rationale, consequences, alternatives);
    this.records.set(id, adr);
    return adr;
  }

  accept(id) {
    const adr = this.records.get(id);
    if (!adr) throw new Error(`ADR-${id} 不存在`);
    adr.accept();
    return adr;
  }

  supersede(oldId, newTitle, newContext, newDecision, newRationale, newConsequences, newAlternatives) {
    const oldAdr = this.records.get(oldId);
    if (!oldAdr) throw new Error(`ADR-${oldId} 不存在`);

    const newAdr = this.create(newTitle, newContext, newDecision, newRationale, newConsequences, newAlternatives);
    newAdr.accept();
    oldAdr.supersede(newAdr.id);
    return { oldAdr, newAdr };
  }

  // 查询所有有效的决策
  getActiveDecisions() {
    return Array.from(this.records.values()).filter(adr => adr.status === 'accepted');
  }

  // 生成 ADR 索引
  printIndex() {
    console.log(`\n=== ${this.projectName} ADR 索引 ===\n`);
    const statusIcons = {
      proposed: '📋',
      accepted: '✅',
      deprecated: '⚠️',
      superseded: '🔄',
    };

    for (const adr of this.records.values()) {
      const icon = statusIcons[adr.status];
      let line = `${icon} ADR-${adr.id}: ${adr.title} [${adr.status}]`;
      if (adr.supersededBy) line += ` → ADR-${adr.supersededBy}`;
      console.log(line);
    }
  }

  // 打印完整 ADR
  printAdr(id) {
    const adr = this.records.get(id);
    if (!adr) throw new Error(`ADR-${id} 不存在`);
    console.log(adr.toMarkdown());
  }
}
```

## ⚖️ 权衡分析方法

### 权衡矩阵（Trade-off Matrix）

权衡矩阵是一种系统化的决策工具，通过**量化评分**来比较多个备选方案。

### 代码示例：权衡分析工具

```js
// ========== 权衡分析矩阵 ==========

class TradeoffMatrix {
  constructor(decisionTitle) {
    this.decisionTitle = decisionTitle;
    this.criteria = [];     // 评估维度
    this.candidates = [];   // 候选方案
    this.scores = {};       // 评分数据
  }

  // 添加评估维度和权重
  addCriterion(name, weight, description) {
    if (weight < 0 || weight > 1) throw new Error('权重必须在 0-1 之间');
    this.criteria.push({ name, weight, description });
  }

  // 添加候选方案
  addCandidate(name, description) {
    this.candidates.push({ name, description });
    this.scores[name] = {};
  }

  // 为候选方案的某个维度打分（1-5 分）
  score(candidateName, criterionName, score, justification) {
    if (score < 1 || score > 5) throw new Error('评分必须在 1-5 之间');
    this.scores[candidateName][criterionName] = { score, justification };
  }

  // 计算加权总分
  calculateWeightedScores() {
    const results = [];

    for (const candidate of this.candidates) {
      let totalWeightedScore = 0;
      const details = [];

      for (const criterion of this.criteria) {
        const scoreData = this.scores[candidate.name][criterion.name];
        if (!scoreData) {
          throw new Error(`缺少 ${candidate.name} 在 ${criterion.name} 维度的评分`);
        }
        const weightedScore = scoreData.score * criterion.weight;
        totalWeightedScore += weightedScore;
        details.push({
          criterion: criterion.name,
          weight: criterion.weight,
          rawScore: scoreData.score,
          weightedScore: Math.round(weightedScore * 100) / 100,
          justification: scoreData.justification,
        });
      }

      results.push({
        candidate: candidate.name,
        description: candidate.description,
        totalScore: Math.round(totalWeightedScore * 100) / 100,
        details,
      });
    }

    return results.sort((a, b) => b.totalScore - a.totalScore);
  }

  // 生成报告
  generateReport() {
    console.log(`\n${'='.repeat(60)}`);
    console.log(`⚖️ 权衡分析: ${this.decisionTitle}`);
    console.log(`${'='.repeat(60)}`);

    // 评估维度
    console.log('\n📐 评估维度:');
    const totalWeight = this.criteria.reduce((sum, c) => sum + c.weight, 0);
    for (const criterion of this.criteria) {
      const percentage = ((criterion.weight / totalWeight) * 100).toFixed(0);
      console.log(`  - ${criterion.name} (权重: ${percentage}%): ${criterion.description}`);
    }

    // 评分结果
    const results = this.calculateWeightedScores();
    console.log('\n📊 评分结果（从高到低）:\n');

    for (let i = 0; i < results.length; i++) {
      const result = results[i];
      const medal = i === 0 ? '🥇' : i === 1 ? '🥈' : '🥉';
      console.log(`${medal} ${result.candidate} — 总分: ${result.totalScore}`);
      console.log(`   ${result.description}`);
      for (const detail of result.details) {
        const bar = '█'.repeat(detail.rawScore) + '░'.repeat(5 - detail.rawScore);
        console.log(`   ${detail.criterion}: ${bar} ${detail.rawScore}/5 (加权: ${detail.weightedScore}) — ${detail.justification}`);
      }
      console.log();
    }

    // 推荐
    const winner = results[0];
    const runnerUp = results[1];
    const scoreDiff = winner.totalScore - (runnerUp ? runnerUp.totalScore : 0);
    console.log(`${'='.repeat(60)}`);
    console.log(`📌 推荐方案: ${winner.candidate} (总分 ${winner.totalScore})`);
    if (runnerUp && scoreDiff < 0.5) {
      console.log(`⚠️ 注意: 与第二名 ${runnerUp.candidate} 差距仅 ${scoreDiff.toFixed(2)}，建议进一步论证`);
    }
    console.log(`${'='.repeat(60)}`);

    return results;
  }
}
```

## 🧭 技术选型方法论

### 选型流程

```
1. 明确需求和约束条件
    ↓
2. 调研候选方案（至少 3 个）
    ↓
3. 定义评估维度和权重
    ↓
4. PoC 验证（关键方案需要原型验证）
    ↓
5. 权衡分析和评分
    ↓
6. 团队评审和决策
    ↓
7. 记录 ADR
```

```js
// ========== 技术选型清单 ==========

class TechSelectionChecklist {
  constructor(topic) {
    this.topic = topic;
    this.requirements = [];
    this.constraints = [];
    this.evaluationDimensions = [];
    this.pocPlan = null;
  }

  // 第 1 步：明确需求
  addRequirement(category, description, priority) {
    this.requirements.push({ category, description, priority });
  }

  // 第 1 步：明确约束
  addConstraint(description) {
    this.constraints.push(description);
  }

  // 第 3 步：定义评估维度
  addEvaluationDimension(name, questions) {
    this.evaluationDimensions.push({ name, questions });
  }

  // 第 4 步：定义 PoC 计划
  setPocPlan(duration, scope, successCriteria) {
    this.pocPlan = { duration, scope, successCriteria };
  }

  printChecklist() {
    console.log(`\n${'='.repeat(50)}`);
    console.log(`🧭 技术选型清单: ${this.topic}`);
    console.log(`${'='.repeat(50)}`);

    console.log('\n📋 需求:');
    const priorityIcon = { must: '🔴', should: '🟡', nice: '🟢' };
    for (const req of this.requirements) {
      console.log(`  ${priorityIcon[req.priority]} [${req.category}] ${req.description}`);
    }

    console.log('\n🔒 约束条件:');
    for (const constraint of this.constraints) {
      console.log(`  ⚠️ ${constraint}`);
    }

    console.log('\n📐 评估维度:');
    for (const dim of this.evaluationDimensions) {
      console.log(`  📌 ${dim.name}`);
      for (const question of dim.questions) {
        console.log(`     ❓ ${question}`);
      }
    }

    if (this.pocPlan) {
      console.log('\n🧪 PoC 计划:');
      console.log(`  时长: ${this.pocPlan.duration}`);
      console.log(`  范围: ${this.pocPlan.scope}`);
      console.log('  成功标准:');
      for (const criterion of this.pocPlan.successCriteria) {
        console.log(`    ✅ ${criterion}`);
      }
    }
  }
}
```

## 📚 ADR 管理最佳实践

### 1. ADR 存放位置

```
项目根目录/
├── docs/
│   └── adr/
│       ├── 001-choose-kafka-as-message-queue.md
│       ├── 002-choose-mysql-as-primary-database.md
│       ├── 003-use-session-authentication.md
│       ├── 004-switch-to-jwt-authentication.md
│       └── index.md         ← ADR 索引页
```

### 2. 命名规范

- 文件名格式：`{编号}-{简短描述}.md`
- 编号连续递增，不重用
- 描述使用 kebab-case

### 3. 什么决策需要记录 ADR？

| 需要记录 | 不需要记录 |
|---------|-----------|
| 技术栈选型（语言、框架、中间件） | 变量命名、代码风格 |
| 架构风格选择（单体/微服务） | 具体的 UI 布局调整 |
| 数据存储方案（数据库、缓存） | 日常 Bug 修复 |
| 认证授权方案 | 小型重构 |
| 通信协议选择（REST/gRPC） | 性能微调 |
| 部署策略变更 | 依赖版本升级 |
