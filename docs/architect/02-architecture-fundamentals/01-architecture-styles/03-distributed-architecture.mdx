## 🏗️ 微服务架构（Microservices）

### 核心思想

微服务架构将应用拆分为一组小型、自治的服务，每个服务围绕特定的业务能力构建，可以独立开发、部署和扩展。

### 架构图示

```
                    ┌─────────────┐
                    │  API 网关    │
                    └──────┬──────┘
            ┌──────────────┼──────────────┐
            ↓              ↓              ↓
     ┌────────────┐ ┌────────────┐ ┌────────────┐
     │  用户服务   │ │  订单服务   │ │  支付服务   │
     │            │ │            │ │            │
     │  独立数据库 │ │  独立数据库 │ │  独立数据库 │
     └────────────┘ └────────────┘ └────────────┘
            ↕              ↕              ↕
     ┌─────────────────────────────────────────┐
     │            消息总线 / 事件流              │
     └─────────────────────────────────────────┘
```

### 微服务的核心原则

| 原则 | 说明 |
|------|------|
| **单一职责** | 每个服务只负责一个业务能力 |
| **自治性** | 服务可以独立开发、测试、部署 |
| **去中心化** | 数据管理去中心化，每个服务拥有自己的数据 |
| **容错设计** | 服务故障不应导致整个系统不可用 |
| **可演进** | 服务可以独立演进、替换技术栈 |

### 代码示例：微服务间通信

```js
// ========== 用户服务 ==========
class UserService {
  constructor() {
    this.users = new Map();
    this.nextId = 1;
  }

  // 对外暴露的 HTTP API
  handleRequest(method, path, body) {
    if (method === 'POST' && path === '/users') {
      return this.createUser(body);
    }
    if (method === 'GET' && path.startsWith('/users/')) {
      const userId = path.split('/')[2];
      return this.getUser(userId);
    }
    return { status: 404, body: { message: 'Not Found' } };
  }

  createUser({ name, email }) {
    const userId = `user-${this.nextId++}`;
    this.users.set(userId, { id: userId, name, email });
    return { status: 201, body: { id: userId, name, email } };
  }

  getUser(userId) {
    const user = this.users.get(userId);
    if (!user) return { status: 404, body: { message: '用户不存在' } };
    return { status: 200, body: user };
  }
}

// ========== 订单服务 ==========
class OrderService {
  constructor(serviceRegistry) {
    this.orders = new Map();
    this.nextId = 1;
    this.serviceRegistry = serviceRegistry;
  }

  async createOrder(userId, items) {
    // 跨服务调用：验证用户是否存在
    const userResponse = await this.serviceRegistry.call('user-service', 'GET', `/users/${userId}`);
    if (userResponse.status !== 200) {
      return { status: 400, body: { message: '用户不存在，无法创建订单' } };
    }

    const totalAmount = items.reduce((sum, item) => sum + item.price * item.quantity, 0);
    const orderId = `order-${this.nextId++}`;
    const order = {
      id: orderId,
      userId,
      userName: userResponse.body.name,
      items,
      totalAmount,
      status: 'created',
      createdAt: new Date().toISOString(),
    };
    this.orders.set(orderId, order);
    return { status: 201, body: order };
  }
}

// ========== 服务注册与发现（简化实现）==========
class ServiceRegistry {
  constructor() {
    this.services = new Map();
  }

  register(serviceName, serviceInstance) {
    this.services.set(serviceName, serviceInstance);
    console.log(`[注册中心] 服务 ${serviceName} 已注册`);
  }

  async call(serviceName, method, path, body) {
    const service = this.services.get(serviceName);
    if (!service) {
      throw new Error(`服务 ${serviceName} 未注册`);
    }
    return service.handleRequest(method, path, body);
  }
}

// ========== 组装与运行 ==========
const registry = new ServiceRegistry();

const userService = new UserService();
registry.register('user-service', userService);

const orderService = new OrderService(registry);

// 创建用户
userService.handleRequest('POST', '/users', { name: '李四', email: 'lisi@example.com' });

// 创建订单（跨服务调用验证用户）
orderService.createOrder('user-1', [
  { name: '显示器', price: 2499, quantity: 1 },
]).then(result => console.log('订单结果:', JSON.stringify(result, null, 2)));
```

### 微服务拆分策略

**按业务能力拆分**：
```
电商系统
  ├── 用户服务（注册、登录、个人信息）
  ├── 商品服务（商品管理、搜索、库存）
  ├── 订单服务（下单、订单查询、状态管理）
  ├── 支付服务（支付、退款、对账）
  ├── 物流服务（发货、物流追踪）
  └── 通知服务（短信、邮件、推送）
```

**按子域拆分（DDD 方法）**：
```
核心子域  → 自建：订单、支付（竞争优势）
支撑子域  → 自建或外包：物流、客服
通用子域  → 购买/开源：认证、通知、日志
```

### 微服务的挑战

1. **分布式复杂性**：网络延迟、部分失败、数据一致性
2. **运维开销**：需要成熟的 CI/CD、监控、日志体系
3. **服务间通信**：需要处理超时、重试、熔断
4. **数据一致性**：跨服务事务需要 Saga 等模式
5. **测试困难**：集成测试和端到端测试复杂度高

## 📡 面向服务架构（SOA）

### SOA vs 微服务

SOA 和微服务都是分布式架构，但在理念和实现上有显著差异：

| 维度 | SOA | 微服务 |
|------|-----|--------|
| **服务粒度** | 粗粒度，一个服务可能涵盖多个业务流程 | 细粒度，一个服务只负责一个业务能力 |
| **通信方式** | ESB（企业服务总线）集中式 | 轻量级协议（HTTP/gRPC）点对点 |
| **数据管理** | 通常共享数据库 | 每个服务独立数据库 |
| **治理模式** | 集中治理 | 去中心化治理 |
| **部署** | 通常整体部署或大服务部署 | 独立部署 |
| **技术栈** | 倾向统一技术栈 | 允许多技术栈 |

### SOA 的架构特征

```
┌────────────────────────────────────────────────┐
│                    消费者                        │
└──────────────────────┬─────────────────────────┘
                       ↓
┌────────────────────────────────────────────────┐
│              企业服务总线（ESB）                  │
│   路由 │ 转换 │ 编排 │ 协议转换 │ 安全          │
└──┬───────────┬───────────┬───────────┬─────────┘
   ↓           ↓           ↓           ↓
┌──────┐  ┌──────┐   ┌──────┐   ┌──────┐
│服务 A │  │服务 B │   │服务 C │   │服务 D │
│(CRM) │  │(ERP) │   │(HR)  │   │(财务) │
└──────┘  └──────┘   └──────┘   └──────┘
```

### ESB 的角色

```js
// ESB 简化示例：集中式消息路由和协议转换

class EnterpriseServiceBus {
  constructor() {
    this.routes = new Map();
    this.transformers = new Map();
  }

  // 注册服务路由
  registerRoute(operationName, targetService, transformer) {
    this.routes.set(operationName, targetService);
    if (transformer) {
      this.transformers.set(operationName, transformer);
    }
  }

  // ESB 核心职责：路由 + 转换 + 调用
  async invoke(operationName, requestData) {
    console.log(`[ESB] 收到操作请求: ${operationName}`);

    const targetService = this.routes.get(operationName);
    if (!targetService) {
      throw new Error(`未找到操作 ${operationName} 的路由`);
    }

    // 消息转换（如果需要）
    const transformer = this.transformers.get(operationName);
    const transformedData = transformer ? transformer(requestData) : requestData;
    console.log(`[ESB] 路由到服务: ${targetService.name}`);

    // 调用目标服务
    return targetService.execute(transformedData);
  }
}

// 服务实现
class CrmService {
  constructor() { this.name = 'CRM'; }
  execute(data) {
    console.log(`[CRM] 处理请求:`, data);
    return { success: true, customerId: 'cust-001', source: 'CRM' };
  }
}

class ErpService {
  constructor() { this.name = 'ERP'; }
  execute(data) {
    console.log(`[ERP] 处理请求:`, data);
    return { success: true, inventoryStatus: 'available', source: 'ERP' };
  }
}

// 组装
const esb = new EnterpriseServiceBus();
const crmService = new CrmService();
const erpService = new ErpService();

// XML 到 JSON 的转换器示例
const legacyTransformer = (data) => ({ ...data, format: 'normalized', timestamp: Date.now() });

esb.registerRoute('getCustomer', crmService, legacyTransformer);
esb.registerRoute('checkInventory', erpService, null);

// 通过 ESB 调用服务
esb.invoke('getCustomer', { customerId: '001' });
esb.invoke('checkInventory', { productId: 'prod-001' });
```

## ⚡ 事件驱动架构（EDA）

### 核心概念

事件驱动架构围绕**事件的产生、检测和消费**来构建系统。组件之间通过事件进行异步通信，实现高度解耦。

### 两种主要拓扑

#### 1. 中介者拓扑（Mediator Topology）

```
事件 → 事件队列 → 中介者(编排) → 事件通道 → 事件处理器
```

适用于需要**多步骤协调**的复杂事件处理。

#### 2. 代理者拓扑（Broker Topology）

```
事件 → 事件代理(广播) → 事件处理器 A
                      → 事件处理器 B
                      → 事件处理器 C
```

适用于**事件处理链相对简单**且不需要集中编排的场景。

### 代码示例：事件驱动系统

```js
// ========== 事件总线 ==========
class EventBus {
  constructor() {
    this.subscribers = new Map();
    this.eventLog = [];
  }

  subscribe(eventType, handler, handlerName) {
    if (!this.subscribers.has(eventType)) {
      this.subscribers.set(eventType, []);
    }
    this.subscribers.get(eventType).push({ handler, handlerName });
    console.log(`[EventBus] ${handlerName} 订阅了 ${eventType}`);
  }

  publish(eventType, eventData) {
    const event = {
      id: `evt-${Date.now()}-${Math.random().toString(36).slice(2, 8)}`,
      type: eventType,
      data: eventData,
      timestamp: new Date().toISOString(),
    };
    this.eventLog.push(event);
    console.log(`\n[EventBus] 发布事件: ${eventType}`, eventData);

    const handlers = this.subscribers.get(eventType) || [];
    for (const { handler, handlerName } of handlers) {
      try {
        handler(event);
      } catch (error) {
        console.error(`[EventBus] ${handlerName} 处理事件 ${eventType} 失败:`, error.message);
      }
    }
  }
}

// ========== 订单服务：产生事件 ==========
class OrderEventProducer {
  constructor(eventBus) {
    this.eventBus = eventBus;
  }

  placeOrder(userId, items) {
    const orderId = `order-${Date.now()}`;
    const totalAmount = items.reduce((sum, item) => sum + item.price * item.quantity, 0);

    // 发布"订单已创建"事件
    this.eventBus.publish('OrderCreated', { orderId, userId, items, totalAmount });
    return orderId;
  }
}

// ========== 库存服务：消费事件 ==========
class InventoryEventHandler {
  constructor(eventBus) {
    eventBus.subscribe('OrderCreated', (event) => this.onOrderCreated(event), '库存服务');
  }

  onOrderCreated(event) {
    const { orderId, items } = event.data;
    console.log(`[库存服务] 收到订单 ${orderId}，正在扣减库存...`);
    for (const item of items) {
      console.log(`  → 扣减 ${item.name} x ${item.quantity}`);
    }
    // 库存扣减成功后，可以继续发布新事件
  }
}

// ========== 通知服务：消费事件 ==========
class NotificationEventHandler {
  constructor(eventBus) {
    eventBus.subscribe('OrderCreated', (event) => this.onOrderCreated(event), '通知服务');
  }

  onOrderCreated(event) {
    const { orderId, userId, totalAmount } = event.data;
    console.log(`[通知服务] 向用户 ${userId} 发送订单确认通知`);
    console.log(`  → 订单号: ${orderId}，金额: ¥${totalAmount}`);
  }
}

// ========== 审计服务：消费事件 ==========
class AuditEventHandler {
  constructor(eventBus) {
    this.auditLog = [];
    eventBus.subscribe('OrderCreated', (event) => this.onAnyEvent(event), '审计服务');
  }

  onAnyEvent(event) {
    this.auditLog.push({ eventId: event.id, type: event.type, timestamp: event.timestamp });
    console.log(`[审计服务] 已记录事件 ${event.type} (${event.id})`);
  }
}

// ========== 组装与运行 ==========
const eventBus = new EventBus();

// 各服务独立订阅感兴趣的事件
new InventoryEventHandler(eventBus);
new NotificationEventHandler(eventBus);
new AuditEventHandler(eventBus);

// 下单
const orderProducer = new OrderEventProducer(eventBus);
orderProducer.placeOrder('user-001', [
  { name: '无线耳机', price: 299, quantity: 1 },
  { name: '手机壳', price: 39, quantity: 2 },
]);
```

### EDA 的优劣势

**优势**：
- **高度解耦**：生产者和消费者互不感知
- **可扩展性**：新增消费者无需修改生产者
- **异步处理**：提升系统吞吐量和响应速度
- **事件溯源**：事件日志可用于审计和调试

**劣势**：
- **最终一致性**：数据不会立即一致
- **调试困难**：事件流难以追踪
- **错误处理复杂**：需要处理重复消费、乱序等问题
- **测试复杂**：异步行为难以确定性测试

## 🕸️ 服务网格（Service Mesh）

### 什么是服务网格？

服务网格是一种**基础设施层**，用于处理微服务之间的通信。它通过在每个服务旁部署一个代理（Sidecar），将网络通信逻辑从业务代码中剥离。

### 架构模型

```
┌──────────────────────────────────────────────────┐
│                  控制平面（Control Plane）          │
│  ┌──────────┐  ┌──────────┐  ┌──────────────┐   │
│  │ 服务发现  │  │ 配置管理  │  │ 证书管理      │   │
│  └──────────┘  └──────────┘  └──────────────┘   │
└─────────────────────┬────────────────────────────┘
                      │ 下发策略
        ┌─────────────┼─────────────┐
        ↓             ↓             ↓
  ┌───────────┐ ┌───────────┐ ┌───────────┐
  │ ┌───────┐ │ │ ┌───────┐ │ │ ┌───────┐ │
  │ │Sidecar│←→│ │Sidecar│←→│ │Sidecar│ │    ← 数据平面
  │ │ Proxy │ │ │ │ Proxy │ │ │ │ Proxy │ │
  │ └───┬───┘ │ │ └───┬───┘ │ │ └───┬───┘ │
  │     ↕     │ │     ↕     │ │     ↕     │
  │ ┌───────┐ │ │ ┌───────┐ │ │ ┌───────┐ │
  │ │服务 A │ │ │ │服务 B │ │ │ │服务 C │ │    ← 业务服务
  │ └───────┘ │ │ └───────┘ │ │ └───────┘ │
  └───────────┘ └───────────┘ └───────────┘
```

### Sidecar 代理的职责

```js
// Sidecar 代理的职责模拟

class SidecarProxy {
  constructor(serviceName, controlPlane) {
    this.serviceName = serviceName;
    this.controlPlane = controlPlane;
    this.requestCount = 0;
    this.circuitState = 'closed'; // closed, open, half-open
    this.failureCount = 0;
    this.failureThreshold = 3;
  }

  // 1. 流量管理：负载均衡
  selectInstance(targetService) {
    const instances = this.controlPlane.getInstances(targetService);
    if (instances.length === 0) {
      throw new Error(`未找到服务 ${targetService} 的可用实例`);
    }
    // 轮询负载均衡
    const index = this.requestCount++ % instances.length;
    return instances[index];
  }

  // 2. 弹性：熔断器
  checkCircuitBreaker() {
    if (this.circuitState === 'open') {
      throw new Error(`[熔断器] 服务 ${this.serviceName} 的熔断器已打开，拒绝请求`);
    }
  }

  recordSuccess() {
    this.failureCount = 0;
    if (this.circuitState === 'half-open') {
      this.circuitState = 'closed';
      console.log(`[熔断器] ${this.serviceName} 恢复为关闭状态`);
    }
  }

  recordFailure() {
    this.failureCount++;
    if (this.failureCount >= this.failureThreshold) {
      this.circuitState = 'open';
      console.log(`[熔断器] ${this.serviceName} 触发熔断！`);
      setTimeout(() => {
        this.circuitState = 'half-open';
        console.log(`[熔断器] ${this.serviceName} 进入半开状态，允许探测请求`);
      }, 5000);
    }
  }

  // 3. 可观测性：指标收集
  collectMetrics(targetService, duration, success) {
    console.log(
      `[指标] ${this.serviceName} → ${targetService} | 耗时: ${duration}ms | 结果: ${success ? '成功' : '失败'}`
    );
  }

  // 4. 安全：mTLS
  establishMutualTls(targetService) {
    console.log(`[安全] ${this.serviceName} ↔ ${targetService} 已建立 mTLS 连接`);
  }

  // 代理请求的完整流程
  async proxyRequest(targetService, request) {
    const startTime = Date.now();
    try {
      this.checkCircuitBreaker();
      this.establishMutualTls(targetService);
      const instance = this.selectInstance(targetService);
      console.log(`[代理] ${this.serviceName} → ${targetService} (实例: ${instance.id})`);

      const response = instance.handle(request);
      this.recordSuccess();
      this.collectMetrics(targetService, Date.now() - startTime, true);
      return response;
    } catch (error) {
      this.recordFailure();
      this.collectMetrics(targetService, Date.now() - startTime, false);
      throw error;
    }
  }
}

// 控制平面
class ControlPlane {
  constructor() {
    this.registry = new Map();
  }

  registerInstance(serviceName, instance) {
    if (!this.registry.has(serviceName)) {
      this.registry.set(serviceName, []);
    }
    this.registry.get(serviceName).push(instance);
  }

  getInstances(serviceName) {
    return this.registry.get(serviceName) || [];
  }
}

// 运行示例
const controlPlane = new ControlPlane();
controlPlane.registerInstance('payment-service', {
  id: 'payment-1',
  handle: (req) => ({ status: 'paid', orderId: req.orderId }),
});
controlPlane.registerInstance('payment-service', {
  id: 'payment-2',
  handle: (req) => ({ status: 'paid', orderId: req.orderId }),
});

const orderProxy = new SidecarProxy('order-service', controlPlane);
orderProxy.proxyRequest('payment-service', { orderId: 'order-001', amount: 599 })
  .then(result => console.log('支付结果:', result));
```

### 主流服务网格方案对比

| 方案 | 数据平面 | 控制平面 | 特点 |
|------|---------|---------|------|
| **Istio** | Envoy | istiod | 功能最全面，社区最大，学习曲线较高 |
| **Linkerd** | linkerd2-proxy (Rust) | control plane | 轻量级，性能优秀，上手简单 |
| **Consul Connect** | Envoy / 内置 | Consul Server | 与 HashiCorp 生态深度集成 |

## 📊 分布式架构风格对比

| 维度 | 微服务 | SOA | 事件驱动 | 服务网格 |
|------|--------|-----|---------|---------|
| **服务粒度** | 细粒度 | 粗粒度 | 事件处理器 | 不限 |
| **耦合度** | 低 | 中 | 极低 | 低 |
| **通信方式** | HTTP/gRPC | ESB | 异步事件 | Sidecar 代理 |
| **数据管理** | 独立数据库 | 共享或独立 | 事件日志 | 不涉及 |
| **一致性** | 最终一致性 | 可强一致 | 最终一致性 | 不涉及 |
| **运维复杂度** | 高 | 中 | 中高 | 高（但自动化） |
| **适用场景** | 大型互联网系统 | 企业集成 | 实时处理 | 微服务治理 |
