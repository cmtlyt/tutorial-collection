# 基础设施即代码（IaC）

> **版本**：v1.1
> **最后更新**：2026-04-28

## 📚 概念介绍

基础设施即代码（Infrastructure as Code，IaC）是一种通过代码来管理和配置基础设施的方法，它将基础设施像应用代码一样进行版本控制、测试和自动化部署。

### 核心原则

- **声明式配置**：描述期望状态而非执行步骤
- **幂等性**：多次执行产生相同结果
- **版本控制**：所有变更都通过 Git 管理
- **自动化测试**：对基础设施代码进行测试验证
- **不可变基础设施**：替换而非修改现有资源

### IaC 工具对比

| 工具 | 类型 | 语言 | 适用场景 | 特点 |
|------|------|------|---------|------|
| **Terraform** | 声明式 | HCL | 云资源管理 | 多云支持、状态管理 |
| **Ansible** | 命令式 | YAML | 配置管理 | 无代理、简单易用 |
| **Puppet** | 声明式 | Ruby DSL | 配置管理 | 强大的依赖管理 |
| **CloudFormation** | 声明式 | YAML/JSON | AWS 专用 | AWS 原生集成 |

## 🧠 IaC 到底在解决什么问题？

### 前 IaC 时代：雪花服务器（Snowflake Server）

在 IaC 普及之前，生产服务器通常长这样：

- 三年前某工程师手工 `apt-get install` 了一堆东西
- 两年前因为某次故障临时 `vim` 改了配置
- 一年前升级内核留下了某些副作用
- 现在还能跑，但**没人敢重启**，也**没人说得清它的状态**

每台服务器像雪花一样独一无二、不可复制——这就是 **Snowflake Server**。它的几个典型症状：
- **不可复现**：你能跑起来一模一样的第二台吗？不能
- **文档永远滞后**：wiki 上写的和实际不一致
- **人走带走一切**：那个懂它的工程师离职了，服务器成孤儿
- **灾备是伪命题**：备份？只能备份数据，备份不了"这台神秘机器是怎么炼成的"

### IaC 的终极愿景：凤凰服务器（Phoenix Server）

Martin Fowler 提出 **Phoenix Server** 概念：像凤凰涅槃一样，**服务器可以随时烧掉重建，新生的和死去的完全一致**。

实现路径：
- 所有配置、软件、依赖**全部写入代码**
- 用 IaC 工具从代码**一键创建**全新环境
- 配置不对？不修，直接销毁重建
- 变更要生效？改代码 → 销毁 → 新建

这直接带来了**不可变基础设施**（Immutable Infrastructure）——构建后永不修改，要变就替换。

## 📜 IaC 的演进史

| 时期 | 代表工具 | 范式 | 局限 |
|------|---------|------|------|
| **脚本时代**（~2005） | Shell / Perl 脚本 | 命令式 | 不幂等，反复执行会出错 |
| **配置管理 1.0**（2005-2013） | Puppet、Chef | 半声明式 | 需装 Agent，聚焦 OS 配置 |
| **配置管理 2.0**（2012-） | Ansible、SaltStack | 轻量、无 Agent | 仍以"配置服务器"为核心 |
| **云资源供应**（2014-） | Terraform、CloudFormation | 声明式 + 状态管理 | 真正实现"基础设施即代码" |
| **Kubernetes 时代**（2016-） | Helm、Kustomize、ArgoCD | 声明式 + GitOps | 仅限 K8s 领域 |

**关键分水岭**是 HashiCorp 在 2014 年发布 **Terraform**——它首次把"声明式 + 状态管理 + 跨云厂商"三件事合在一起，重新定义了 IaC。

## 🏛️ 声明式 vs 命令式：理解 IaC 工具分化的关键

### 命令式（Imperative）：Ansible、Shell 脚本

你告诉工具**"做什么步骤"**：

```
- 检查 nginx 是否安装
- 如果没装，执行 apt install nginx
- 复制配置文件到 /etc/nginx/
- 执行 systemctl restart nginx
```

问题：**执行顺序和条件判断都要你自己管**。不幂等时反复跑会出意外。

### 声明式（Declarative）：Terraform、K8s YAML

你告诉工具**"要达成什么状态"**：

```
"我要一台 t3.medium 的 EC2，跑在 us-east-1a，装了 nginx"
```

工具自己去对比当前状态、计算差异、执行所需动作。

### 两种范式的哲学对比

| 维度 | 命令式 | 声明式 |
|------|-------|-------|
| **描述内容** | HOW（怎么做） | WHAT（要什么） |
| **幂等性** | 需要开发者刻意实现 | 天然幂等 |
| **状态感知** | 每次从零执行 | 有"当前状态"概念 |
| **学习曲线** | 低（像写脚本） | 高（要理解状态管理） |
| **复杂场景扩展** | 容易变成意大利面 | 可组合、可推理 |
| **代表场景** | OS 配置、临时运维 | 云资源供应、K8s |

**为什么声明式成为云原生时代主流？** 因为云资源规模大、生命周期长、依赖关系复杂。命令式思维无法描述"10000 个资源之间的依赖关系"，声明式才能 scale。

## ⚖️ IaC 的核心技术挑战：状态管理

声明式工具的灵魂是"对比 desired 和 current 状态"——但"current state"从哪来？这是 Terraform 与 Ansible 的**本质分野**。

### 无状态模型（Ansible）

每次执行都**实时查询当前状态**。好处：简单、无状态存储负担。坏处：大规模场景极慢（查询 1000 个云资源的耗时巨大）。

### 有状态模型（Terraform）

Terraform 维护一个 **state 文件**（`terraform.tfstate`），记录"我上次创建了哪些资源、它们的 ID 是什么"。

```
本地配置文件 (*.tf)
      │
      ▼
   期望状态
      │                 对比
      │  ◀───────────────────┐
      ▼                      │
   Terraform                 │
      │                      │
      ▼                      │
  state 文件 (tfstate)  ─────┘
      │
      ▼
 实际云资源 (AWS API)
```

### 状态管理带来的三大难题

**难题一：并发修改**
如果两个工程师同时 `terraform apply`，state 文件可能损坏。
**解决**：远程状态 + 分布式锁（Terraform Backend 用 S3 + DynamoDB 锁 / Consul / Terraform Cloud）。

**难题二：状态漂移（Drift）**
有人绕过 Terraform，直接在 AWS 控制台改了资源。下次 `terraform plan` 时，工具看到的"期望"和"现实"对不上。
**解决**：
- 纪律约束：所有变更必须走 Terraform（严格的 CI/CD 卡点）
- 工具支持：`terraform refresh` 重新同步状态、`terraform import` 把手工资源纳入管理
- 周期性 Drift Detection：定期 plan，对比差异并告警

**难题三：敏感信息泄露**
state 文件可能包含数据库密码、私钥等敏感信息。
**解决**：
- state 加密（S3 SSE、Terraform Cloud 加密存储）
- 敏感输出标 `sensitive = true`
- 不在 state 里放秘密，改用 Vault 等秘钥管理器

## 🎯 IaC 的四大基石原则

### 原则一：幂等性（Idempotence）

> 执行 1 次的结果 = 执行 N 次的结果。

这是 IaC 工具的**必要条件**。脚本不幂等就不是 IaC，只是"被版本化的 shell 脚本"。

### 原则二：可重现性（Reproducibility）

相同的代码、相同的环境、相同的输入 → 产出相同的基础设施。
这要求：
- 锁定 provider 版本（`required_version`、`version` 约束）
- 不依赖"当前时间"、"机器本地状态"等外部因素

### 原则三：可组合性（Composability）

复杂的基础设施应由可复用模块（Module）组合而成，而非一个巨型单体文件。
Terraform Module、Ansible Role、Helm Chart 都是这个思想的体现。

### 原则四：自动化测试

基础设施代码也要测：
- **静态检查**：`terraform validate`、`tflint`、`checkov`（安全合规）
- **单元测试**：Terratest（Go）、Kitchen-Terraform
- **集成测试**：在 sandbox 账号跑完整 plan/apply/destroy

## 🌍 IaC 的多环境管理模式

生产不能用开发的配置，但也不能两份互相复制粘贴。业界主流三种模式：

### 模式一：Workspace / Tenant

一套代码，通过 workspace 区分环境（Terraform Workspace、Helm --namespace）。
✅ 简单，代码不重复
❌ 环境差异大时难以处理

### 模式二：目录层级

```
infra/
├── modules/            # 共享模块
└── environments/
    ├── dev/
    ├── staging/
    └── prod/           # 每个环境一个目录，独立 state
```

✅ 环境完全隔离，变更影响明确
❌ 目录结构变复杂

### 模式三：Overlay（Kustomize 模式）

一套 base，各环境只声明 **差异**（patches、overlay）。

✅ DRY，易维护
❌ 需要工具支持（Kustomize、Helm Values 覆盖）

## 🎯 Terraform

### 基础配置

**项目结构：**
```

├── main.tf              # 主配置文件
```

**provider.tf：**
```hcl
terraform {
  required_version = ">= 1.5.0"
  
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
  
  backend "s3" {
    bucket         = "my-terraform-state"
    key            = "prod/terraform.tfstate"
    region         = "us-west-2"
    encrypt        = true
    dynamodb_table = "terraform-locks"
  }
}

provider "aws" {
  region = var.aws_region
  
  default_tags {
    tags = {
      Environment = var.environment
      ManagedBy   = "Terraform"
      Project     = var.project_name
    }
  }
}
```

```hcl
variable "aws_region" {
```

```hcl
# Security Group for Application
resource "aws_security_group" "app" {
  name_prefix = "${var.project_name}-app-"
  vpc_id      = aws_vpc.main.id
  
  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }
  
  ingress {
    from_port   = 443
    to_port     = 443
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }
  
  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
  
  tags = {
    Name = "${var.project_name}-app-sg-${var.environment}"
  }
  
  lifecycle {
    create_before_destroy = true
  }
}

# EC2 Instance
resource "aws_instance" "app" {
  count                  = var.environment == "prod" ? 3 : 1
  ami                    = data.aws_ami.amazon_linux_2.id
  instance_type          = var.instance_type
  subnet_id              = aws_subnet.public[count.index % length(var.availability_zones)].id
  vpc_security_group_ids = [aws_security_group.app.id]
  
  user_data = <<-EOF
              #!/bin/bash
              yum update -y
              yum install -y docker
              systemctl start docker
              systemctl enable docker
              docker run -d -p 80:80 nginx:alpine
              EOF
  
  tags = {
    Name = "${var.project_name}-app-${count.index}-${var.environment}"
  }
}

# Application Load Balancer
resource "aws_lb" "app" {
  name               = "${var.project_name}-alb-${var.environment}"
  internal           = false
  load_balancer_type = "application"
  security_groups    = [aws_security_group.app.id]
  subnets            = aws_subnet.public[*].id
  
  enable_deletion_protection = false
  
  tags = {
    Name = "${var.project_name}-alb-${var.environment}"
  }
}

# Target Group
resource "aws_lb_target_group" "app" {
  name     = "${var.project_name}-tg-${var.environment}"
  port     = 80
  protocol = "HTTP"
  vpc_id   = aws_vpc.main.id
  
  health_check {
    path                = "/"
    interval            = 30
    timeout             = 5
    healthy_threshold   = 2
    unhealthy_threshold = 2
  }
}

# Listener
resource "aws_lb_listener" "app" {
  load_balancer_arn = aws_lb.app.arn
  port              = 80
  protocol          = "HTTP"
  
  default_action {
    type             = "forward"
    target_group_arn = aws_lb_target_group.app.arn
  }
}

# Attach instances to target group
resource "aws_lb_target_group_attachment" "app" {
  count            = length(aws_instance.app)
  target_group_arn = aws_lb_target_group.app.arn
  target_id        = aws_instance.app[count.index].id
  port             = 80
}
```

### Terraform 命令

```bash
# 初始化工作目录
terraform init

# 格式化配置文件
terraform fmt

# 验证配置
terraform validate

# 查看变更计划
terraform plan

# 应用变更
terraform apply

# 自动批准变更
terraform apply -auto-approve

# 查看状态
terraform show

# 列出资源
terraform state list

# 导入现有资源
terraform import aws_instance.app i-1234567890abcdef0

# 销毁资源
terraform destroy

# 查看输出
terraform output load_balancer_dns

# 工作区管理
terraform workspace new dev
terraform workspace list
terraform workspace select dev
```

**playbooks/setup-web.yml：**
```yaml
---
- name: Setup Web Servers
  hosts: web
  become: yes
  vars:
    nginx_version: "1.24"
    app_port: 3000
  
  tasks:
    - name: Update apt cache
      apt:
        update_cache: yes
        cache_valid_time: 3600
    
    - name: Install required packages
      apt:
        name:
          - nginx
          - docker.io
          - docker-compose
        state: present
    
    - name: Start and enable Docker
      systemd:
        name: docker
        state: started
        enabled: yes
    
    - name: Create app directory
      file:
        path: /opt/app
        state: directory
        owner: ubuntu
        group: ubuntu
        mode: '0755'
    
    - name: Copy Docker Compose file
      copy:
        src: docker-compose.yml
        dest: /opt/app/docker-compose.yml
        owner: ubuntu
        group: ubuntu
        mode: '0644'
    
    - name: Pull latest Docker images
      docker_compose:
        project_src: /opt/app
        pull: yes
    
    - name: Start application
      docker_compose:
        project_src: /opt/app
        state: present
    
    - name: Configure Nginx reverse proxy
      template:
        src: nginx.conf.j2
        dest: /etc/nginx/sites-available/app
        owner: root
        group: root
        mode: '0644'
      notify: restart nginx
    
    - name: Enable site
      file:
        src: /etc/nginx/sites-available/app
        dest: /etc/nginx/sites-enabled/app
        state: link
      notify: restart nginx
  
  handlers:
    - name: restart nginx
      systemd:
        name: nginx
        state: restarted
```

**roles/web/templates/nginx.conf.j2：**
```nginx
upstream app {
    server 127.0.0.1:{{ app_port }};
}

server {
    listen 80;
    server_name _;

    location / {
        proxy_pass http://app;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /health {
        access_log off;
        return 200 "healthy\n";
        add_header Content-Type text/plain;
    }
}
```

**playbooks/deploy-app.yml：**
```yaml
---
- name: Deploy Application
  hosts: web
  become: yes
  vars:
    app_version: "{{ lookup('env', 'APP_VERSION') | default('latest', true) }}"
    docker_image: "my-registry/my-app:{{ app_version }}"
  
  tasks:
    - name: Pull new Docker image
      docker_image:
        name: "{{ docker_image }}"
        source: pull
        force_source: yes
    
    - name: Update Docker Compose image
      lineinfile:
        path: /opt/app/docker-compose.yml
        regexp: '^  image:'
        line: '  image: {{ docker_image }}'
    
    - name: Restart application
      docker_compose:
        project_src: /opt/app
        state: present
        restarted: yes
    
    - name: Wait for application to be healthy
      uri:
        url: http://localhost/health
        status_code: 200
      register: result
      until: result.status == 200
      retries: 30
      delay: 5
```

### Ansible 命令

```bash
# 检查连接
ansible all -i inventory/dev.ini -m ping

# 运行 Playbook
ansible-playbook -i inventory/dev.ini playbooks/setup-web.yml

# 指定变量运行
ansible-playbook -i inventory/dev.ini playbooks/deploy-app.yml -e "APP_VERSION=v1.0.0"

# 检查模式（不执行变更）
ansible-playbook -i inventory/dev.ini playbooks/setup-web.yml --check

# 详细输出
ansible-playbook -i inventory/dev.ini playbooks/setup-web.yml -v

# 限制执行的主机
ansible-playbook -i inventory/dev.ini playbooks/setup-web.yml --limit web1.dev.example.com

# 列出主机
ansible all -i inventory/dev.ini --list-hosts

# 在远程主机执行命令
ansible web -i inventory/dev.ini -m shell -a "docker ps"

# 复制文件到远程主机
ansible web -i inventory/dev.ini -m copy -a "src=/local/file dest=/remote/file"
```

```bash
# 修改 Terraform 配置
cd terraform/environments/prod
terraform plan
terraform apply
```
