## 📚 章节介绍

本章节讲解容器化技术和容器编排系统，从 Docker 基础到 Kubernetes 的核心概念和高级特性。

## 🌱 技术演进与时代背景

理解容器与编排，必须从软件部署方式的历史演进切入。每一次飞跃都是在解决上一代的根本矛盾。

### 部署范式四代演进

| 时代 | 代表技术 | 隔离粒度 | 核心矛盾 |
|------|---------|---------|---------|
| **物理机时代**（2000 前） | 裸金属部署 | 进程 | 资源利用率低、环境耦合 |
| **虚拟化时代**（2001-2013） | VMware、Xen、KVM | 操作系统 | 启动慢、镜像重、密度低 |
| **容器时代**（2013-2016） | Docker、LXC | 进程组 | 单机编排能力有限 |
| **编排时代**（2016 至今） | Kubernetes、Nomad | 集群 | 复杂度转移到平台 |

关键历史节点：
- **2006**：AWS EC2 发布，云计算拉开序幕
- **2008**：Linux Container（LXC）项目启动，容器技术走向成熟
- **2013**：Docker 开源发布，用"镜像 + 分层文件系统 + 标准化 API"重新定义容器
- **2014**：Google 开源 Kubernetes（源自内部 Borg/Omega 系统经验）
- **2015**：CNCF（云原生计算基金会）成立，K8s 成为首个孵化项目
- **2020**：Docker 被 K8s 正式弃用（作为运行时），容器运行时标准化为 containerd、CRI-O

### 容器化要解决的根本问题

容器不是为了"节省资源"（VM 已经做到了），而是解决**软件交付一致性**：

- **环境漂移**：开发机跑得好、测试环境挂掉、生产环境再挂（著名的 "It works on my machine"）
- **依赖地狱**：同一台机器的两个应用需要不同版本的 Python/Node/glibc
- **交付割裂**：Dev 交付代码、Ops 交付环境、中间的依赖靠文档和口口相传

Docker 的本质贡献是给出了**标准化的软件交付单元**——镜像（Image），让"构建一次，到处运行"（Build Once, Run Anywhere）从口号变成现实。

## 🧭 云原生（Cloud Native）定义

CNCF 官方定义（v1.1）：

> 云原生技术有利于各组织在公有云、私有云和混合云等新型动态环境中，构建和运行**可弹性扩展**的应用。云原生的代表技术包括**容器、服务网格、微服务、不可变基础设施和声明式 API**。

五大核心支柱（从底层到上层）：

1. **容器化**：应用 + 依赖打包为标准单元（解决交付问题）
2. **不可变基础设施**：构建后永不修改，要变就替换（解决配置漂移）
3. **微服务**：按业务能力拆分独立服务（解决规模扩展问题）
4. **声明式 API**：描述"期望状态"而非"执行步骤"（解决复杂度控制问题）
5. **服务网格/可观测性**：运维能力下沉到基础设施（解决运维复杂度）

## 🎯 编排的本质：从"一台机器"到"一个集群"

单机容器（docker run）好比"一个人手动搬砖"，编排好比"盖楼的项目经理"。编排系统要回答四个核心问题：

| 问题 | 编排器职责 | K8s 对应机制 |
|------|-----------|-------------|
| **跑在哪？** | 从集群中选一台合适的机器 | Scheduler 调度器 |
| **跑不起来怎么办？** | 自动重启、替换、迁移 | Controller 控制循环 |
| **用户怎么访问？** | 提供稳定的网络入口与负载均衡 | Service / Ingress |
| **配置和数据怎么管？** | 解耦配置、持久化存储 | ConfigMap / PV |

理解这四个问题，就掌握了所有编排系统（K8s、Nomad、Mesos、Docker Swarm）的设计母题。它们的差异只是在每个维度上做了不同的取舍。

## 🔑 核心概念

### Kubernetes 核心架构

```
Control Plane
├── API Server（集群入口）
├── etcd（状态存储）
├── Scheduler（调度器）
└── Controller Manager（控制器）

Worker Node
├── kubelet（节点代理）
├── kube-proxy（网络代理）
└── Container Runtime（容器运行时）
```

### 核心资源对象

| 资源 | 用途 | 关键特性 |
|------|------|---------|
| **Pod** | 最小调度单元 | 包含一个或多个容器 |
| **Deployment** | 无状态应用管理 | 滚动更新、回滚 |
| **StatefulSet** | 有状态应用管理 | 稳定网络标识、有序部署 |
| **Service** | 服务发现与负载均衡 | ClusterIP、NodePort、LoadBalancer |
| **Ingress** | HTTP 路由 | 域名、路径路由 |
