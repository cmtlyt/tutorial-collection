## 🤔 为什么需要分布式事务

在单体应用中，一个数据库事务就能保证 ACID。但在微服务架构下，一个业务操作可能跨越多个服务和数据库：

```
用户下单流程（跨 3 个服务）：
  订单服务 → 创建订单（数据库 A）
  库存服务 → 扣减库存（数据库 B）
  账户服务 → 扣减余额（数据库 C）

  问题：库存扣减成功但余额扣减失败，怎么办？
```

分布式事务的目标就是在跨服务、跨数据库的场景下保证数据一致性。

## 🔄 2PC（两阶段提交）

### 工作原理

```
协调者（Transaction Manager）              参与者（Resource Manager）
         │                                    RM1       RM2       RM3
         │                                     │         │         │
阶段一：  │─── Prepare（准备）──────────────→  │         │         │
Prepare  │                                    │ 锁资源   │ 锁资源   │ 锁资源
         │←── Vote Yes/No ──────────────────  │         │         │
         │                                    │         │         │
阶段二：  │─── Commit/Rollback ────────────→  │         │         │
Commit   │                                    │ 提交     │ 提交     │ 提交
         │←── Ack ─────────────────────────   │         │         │
```

### 代码示例

```js
// ========== 两阶段提交（2PC）实现 ==========

class TransactionParticipant {
  constructor(name) {
    this.name = name;
    this.data = new Map();
    this.preparedChanges = null;  // 暂存的变更
    this.locked = false;
  }

  // 阶段一：准备（锁定资源，预执行，但不提交）
  prepare(changes) {
    console.log(`  [${this.name}] 收到 Prepare 请求`);

    // 模拟资源检查
    if (changes.validate) {
      const valid = changes.validate(this.data);
      if (!valid) {
        console.log(`  [${this.name}] ❌ 预检查失败，投票 No`);
        return { vote: 'no', reason: '业务校验失败' };
      }
    }

    // 锁定资源，暂存变更
    this.locked = true;
    this.preparedChanges = changes;
    console.log(`  [${this.name}] ✅ 资源已锁定，投票 Yes`);
    return { vote: 'yes' };
  }

  // 阶段二：提交
  commit() {
    if (!this.preparedChanges) return;

    // 应用变更
    if (this.preparedChanges.apply) {
      this.preparedChanges.apply(this.data);
    }
    this.preparedChanges = null;
    this.locked = false;
    console.log(`  [${this.name}] ✅ 事务已提交`);
  }

  // 阶段二：回滚
  rollback() {
    this.preparedChanges = null;
    this.locked = false;
    console.log(`  [${this.name}] ↩️ 事务已回滚`);
  }
}

class TwoPhaseCommitCoordinator {
  constructor() {
    this.participants = [];
    this.transactionLog = [];
  }

  addParticipant(participant) {
    this.participants.push(participant);
  }

  // 执行分布式事务
  execute(changesList) {
    const transactionId = `txn-${Date.now()}`;
    console.log(`\n=== 分布式事务 ${transactionId} 开始 ===`);

    // 阶段一：Prepare
    console.log('\n--- 阶段一: Prepare ---');
    const votes = [];

    for (let i = 0; i < this.participants.length; i++) {
      const vote = this.participants[i].prepare(changesList[i]);
      votes.push(vote);
      this.transactionLog.push({
        transactionId,
        phase: 'prepare',
        participant: this.participants[i].name,
        vote: vote.vote,
      });
    }

    // 决策
    const allYes = votes.every(v => v.vote === 'yes');

    // 阶段二：Commit 或 Rollback
    if (allYes) {
      console.log('\n--- 阶段二: Commit（所有参与者投票 Yes）---');
      for (const participant of this.participants) {
        participant.commit();
      }
      this.transactionLog.push({ transactionId, phase: 'commit', decision: 'commit' });
      console.log(`\n=== 事务 ${transactionId} 提交成功 ===`);
      return { success: true, transactionId };
    }

    console.log('\n--- 阶段二: Rollback（存在参与者投票 No）---');
    const failedVotes = votes
      .map((v, i) => ({ ...v, participant: this.participants[i].name }))
      .filter(v => v.vote === 'no');

    for (const participant of this.participants) {
      participant.rollback();
    }
    this.transactionLog.push({ transactionId, phase: 'rollback', decision: 'rollback' });
    console.log(`\n=== 事务 ${transactionId} 已回滚 ===`);
    return { success: false, transactionId, reason: failedVotes };
  }
}

// ========== 模拟下单场景 ==========
const coordinator = new TwoPhaseCommitCoordinator();

const orderService = new TransactionParticipant('订单服务');
const inventoryService = new TransactionParticipant('库存服务');
const accountService = new TransactionParticipant('账户服务');

// 初始化数据
inventoryService.data.set('product-001', { stock: 10 });
accountService.data.set('user-001', { balance: 500 });

coordinator.addParticipant(orderService);
coordinator.addParticipant(inventoryService);
coordinator.addParticipant(accountService);

// 场景 1：正常下单
console.log('===== 场景 1：正常下单 =====');
coordinator.execute([
  {
    apply: (data) => data.set('order-001', { product: 'product-001', quantity: 2, amount: 200 }),
  },
  {
    validate: (data) => data.get('product-001').stock >= 2,
    apply: (data) => { data.get('product-001').stock -= 2; },
  },
  {
    validate: (data) => data.get('user-001').balance >= 200,
    apply: (data) => { data.get('user-001').balance -= 200; },
  },
]);

console.log('库存:', inventoryService.data.get('product-001'));
console.log('余额:', accountService.data.get('user-001'));

// 场景 2：余额不足
console.log('\n===== 场景 2：余额不足 =====');
accountService.data.set('user-002', { balance: 50 });  // 余额不足
coordinator.execute([
  {
    apply: (data) => data.set('order-002', { product: 'product-001', quantity: 1, amount: 100 }),
  },
  {
    validate: (data) => data.get('product-001').stock >= 1,
    apply: (data) => { data.get('product-001').stock -= 1; },
  },
  {
    validate: (data) => data.get('user-002')?.balance >= 100,
    apply: (data) => { data.get('user-002').balance -= 100; },
  },
]);
```

### 2PC 的问题

| 问题 | 说明 |
|------|------|
| **同步阻塞** | 所有参与者在 Prepare 后锁定资源，等待协调者决策 |
| **单点故障** | 协调者宕机，参与者无法得知最终决策 |
| **数据不一致** | 阶段二部分参与者收到 Commit、部分没收到 |
| **性能差** | 两轮网络通信 + 资源长时间锁定 |

## 🔄 3PC（三阶段提交）

3PC 在 2PC 的基础上增加了 **CanCommit** 阶段和**超时机制**：

```
阶段一 CanCommit：询问参与者是否能提交（不锁资源）
阶段二 PreCommit：参与者锁定资源、预执行
阶段三 DoCommit：正式提交

改进：
  - 参与者有超时机制：超时后自动提交（减少阻塞）
  - CanCommit 阶段不锁资源（降低锁占用时间）

局限：
  - 仍然无法完全解决网络分区下的一致性问题
  - 工程中较少使用，通常选择 2PC 或 Saga
```

## 🎭 Saga 模式

### 核心思想

Saga 将一个分布式事务拆分为**一系列本地事务**，每个本地事务都有对应的**补偿事务（Compensation）**。如果某个步骤失败，按逆序执行已完成步骤的补偿事务。

### 两种实现方式

```
编排式（Orchestration）：有一个中央协调器
  协调器 → 步骤1 → 步骤2 → 步骤3
  如果步骤3失败：协调器 → 补偿2 → 补偿1

协同式（Choreography）：通过事件驱动，无中央协调
  服务1完成 → 发事件 → 服务2监听并执行
  服务2完成 → 发事件 → 服务3监听并执行
  服务3失败 → 发补偿事件 → 服务2补偿 → 服务1补偿
```

### 代码示例：编排式 Saga

```js
// ========== 编排式 Saga 实现 ==========

class SagaStep {
  constructor(name, executeFn, compensateFn) {
    this.name = name;
    this.executeFn = executeFn;
    this.compensateFn = compensateFn;
    this.executed = false;
  }

  async execute(context) {
    console.log(`  [执行] ${this.name}`);
    const result = this.executeFn(context);
    this.executed = true;
    return result;
  }

  async compensate(context) {
    if (!this.executed) return;
    console.log(`  [补偿] ${this.name}`);
    this.compensateFn(context);
    this.executed = false;
  }
}

class SagaOrchestrator {
  constructor(sagaName) {
    this.sagaName = sagaName;
    this.steps = [];
  }

  addStep(name, executeFn, compensateFn) {
    this.steps.push(new SagaStep(name, executeFn, compensateFn));
    return this;
  }

  execute(context) {
    console.log(`\n=== Saga "${this.sagaName}" 开始 ===`);
    const executedSteps = [];

    for (const step of this.steps) {
      try {
        step.execute(context);
        executedSteps.push(step);
      } catch (error) {
        console.log(`\n  ❌ 步骤 "${step.name}" 失败: ${error.message}`);
        console.log('  开始补偿...\n');

        // 逆序补偿已执行的步骤
        for (let i = executedSteps.length - 1; i >= 0; i--) {
          executedSteps[i].compensate(context);
        }

        console.log(`\n=== Saga "${this.sagaName}" 已回滚 ===`);
        return { success: false, failedStep: step.name, error: error.message };
      }
    }

    console.log(`\n=== Saga "${this.sagaName}" 成功完成 ===`);
    return { success: true };
  }
}

// ========== 下单 Saga ==========

  .addStep(
    '创建订单',

    },

      ctx.order.status = 'cancelled';
      console.log(`    订单已取消: ${ctx.orderId}`);
    },
  )
  .addStep(
    '扣减库存',
    (ctx) => {
      if (ctx.inventory.stock < ctx.quantity) {
        throw new Error('库存不足');
      }
      ctx.inventory.stock -= ctx.quantity;
      console.log(`    库存扣减: ${ctx.quantity}，剩余: ${ctx.inventory.stock}`);
    },
    (ctx) => {
      ctx.inventory.stock += ctx.quantity;
      console.log(`    库存恢复: +${ctx.quantity}，当前: ${ctx.inventory.stock}`);
    },
  )
  .addStep(
    '核销优惠券',

      ctx.coupon.used = true;
```

## 💰 TCC 模式（Try-Confirm-Cancel）

### 核心思想

TCC 将事务分为三个阶段，每个阶段都由业务代码控制：

| 阶段 | 说明 | 示例（转账 100 元） |
|------|------|-------------------|
| **Try** | 预留资源（不真正执行） | 冻结 A 账户 100 元 |
| **Confirm** | 确认执行（使用预留的资源） | A 扣款 100，B 加款 100 |
| **Cancel** | 释放预留的资源 | 解冻 A 账户 100 元 |

### 代码示例

```js
// ========== TCC 模式实现 ==========

class TccAccount {
  constructor(accountId, balance) {
    this.accountId = accountId;
    this.balance = balance;
    this.frozenAmount = 0;    // 冻结金额
    this.frozenDetails = [];  // 冻结明细
  }

  // Try：冻结金额
  tryFreeze(transactionId, amount) {
    const available = this.balance - this.frozenAmount;
    if (available < amount) {
      throw new Error(`账户 ${this.accountId} 可用余额不足: 需要 ${amount}，可用 ${available}`);
    }

    this.frozenAmount += amount;
    this.frozenDetails.push({ transactionId, amount, type: 'freeze' });
    console.log(`  [Try] ${this.accountId}: 冻结 ${amount}（余额: ${this.balance}, 冻结: ${this.frozenAmount}）`);
    return true;
  }

  // Confirm：确认扣款（将冻结金额真正扣除）
  confirmDeduct(transactionId, amount) {
    const freezeRecord = this.frozenDetails.find(d => d.transactionId === transactionId);
    if (!freezeRecord) {
      console.log(`  [Confirm] ${this.accountId}: 未找到冻结记录，可能已处理（幂等）`);
      return;
    }

    this.balance -= amount;
    this.frozenAmount -= amount;
    this.frozenDetails = this.frozenDetails.filter(d => d.transactionId !== transactionId);
    console.log(`  [Confirm] ${this.accountId}: 扣款 ${amount}（余额: ${this.balance}）`);
  }

  // Confirm：确认入账
  confirmCredit(transactionId, amount) {
    this.balance += amount;
    console.log(`  [Confirm] ${this.accountId}: 入账 ${amount}（余额: ${this.balance}）`);
  }

  // Cancel：解冻
  cancelFreeze(transactionId, amount) {
    const freezeRecord = this.frozenDetails.find(d => d.transactionId === transactionId);
    if (!freezeRecord) {
      console.log(`  [Cancel] ${this.accountId}: 未找到冻结记录，可能已处理（幂等）`);
      return;
    }

    this.frozenAmount -= amount;
    this.frozenDetails = this.frozenDetails.filter(d => d.transactionId !== transactionId);
    console.log(`  [Cancel] ${this.accountId}: 解冻 ${amount}（冻结: ${this.frozenAmount}）`);
  }

  getStatus() {
    return {
      accountId: this.accountId,
      balance: this.balance,
      frozenAmount: this.frozenAmount,
      available: this.balance - this.frozenAmount,
    };
  }
}

class TccTransactionManager {
  transfer(transactionId, fromAccount, toAccount, amount) {
    console.log(`\n=== TCC 转账: ${fromAccount.accountId} → ${toAccount.accountId}，金额 ${amount} ===`);

    // 阶段一：Try
    console.log('\n--- Try 阶段 ---');
    try {
      fromAccount.tryFreeze(transactionId, amount);
      // toAccount 的 Try 阶段可以是空操作（或预分配额度）
      console.log(`  [Try] ${toAccount.accountId}: 预留入账空间`);
    } catch (error) {
      console.log(`\n  ❌ Try 失败: ${error.message}`);
      // Try 失败：Cancel 已经 Try 成功的操作
      console.log('\n--- Cancel 阶段 ---');
      fromAccount.cancelFreeze(transactionId, amount);
      return { success: false, error: error.message };
    }

    // 阶段二：Confirm
    console.log('\n--- Confirm 阶段 ---');
    try {
      fromAccount.confirmDeduct(transactionId, amount);
      toAccount.confirmCredit(transactionId, amount);
      console.log('\n=== 转账成功 ===');
      return { success: true };
    } catch (error) {
      // Confirm 失败：需要人工介入或重试（Confirm 应该被设计为幂等的）
      console.log(`\n  ⚠️ Confirm 异常: ${error.message}（需要重试或人工介入）`);
      return { success: false, error: error.message, needManualIntervention: true };
    }
  }
}

// 演示
const alice = new TccAccount('Alice', 1000);
const bob = new TccAccount('Bob', 500);
const tccManager = new TccTransactionManager();

// 场景 1：正常转账
tccManager.transfer('txn-001', alice, bob, 200);
console.log('Alice:', alice.getStatus());
console.log('Bob:', bob.getStatus());

// 场景 2：余额不足
tccManager.transfer('txn-002', alice, bob, 5000);
console.log('Alice:', alice.getStatus());
console.log('Bob:', bob.getStatus());

// 场景 3：并发冻结
console.log('\n===== 并发冻结场景 =====');
const charlie = new TccAccount('Charlie', 300);
const dave = new TccAccount('Dave', 100);
// 两个并发转账都尝试冻结 Charlie 的钱
tccManager.transfer('txn-003', charlie, dave, 200);
tccManager.transfer('txn-004', charlie, dave, 200); // 可用余额不足
console.log('Charlie:', charlie.getStatus());
```

### TCC 的设计要求

| 要求 | 说明 |
|------|------|
| **幂等性** | Try/Confirm/Cancel 都必须幂等（允许重复调用） |
| **空回滚** | Cancel 时可能 Try 还没执行，Cancel 要能处理这种情况 |
| **悬挂** | Cancel 先到达、Try 后到达，Try 不能再执行 |
| **业务侵入** | 需要为每个业务操作编写 Try/Confirm/Cancel 三个方法 |

## 📋 本地消息表

### 核心思想

将分布式事务转化为**本地事务 + 消息**的组合：业务操作和消息写入在同一个本地事务中完成，再通过定时任务或消息队列异步通知下游。

### 代码示例

```js
// ========== 本地消息表实现 ==========

class LocalMessageTable {
  constructor(serviceName) {
    this.serviceName = serviceName;
    this.businessData = new Map();     // 业务数据
    this.messageTable = [];            // 本地消息表
    this.processedMessages = new Set(); // 已处理的消息（幂等表）
  }

  // 核心：业务操作和消息写入在同一"事务"中
  executeWithMessage(businessOperation, message) {
    console.log(`[${this.serviceName}] 开始本地事务`);

    try {
      // 步骤 1：执行业务操作
      businessOperation(this.businessData);

      // 步骤 2：写入本地消息表（同一事务）
      const messageEntry = {
        id: message.id || `msg-${Date.now()}-${Math.random().toString(36).slice(2, 6)}`,
        topic: message.topic,
        body: message.body,
        status: 'pending',   // pending → sent → confirmed
        retryCount: 0,
        maxRetries: 5,
        createdAt: Date.now(),
        updatedAt: Date.now(),
      };
      this.messageTable.push(messageEntry);

      console.log(`  ✅ 业务操作成功 + 消息已写入本地表`);
      console.log(`  消息: [${messageEntry.id}] ${messageEntry.topic}: ${JSON.stringify(messageEntry.body)}`);
      return { success: true, messageId: messageEntry.id };
    } catch (error) {
      // 事务回滚：业务操作和消息都不生效
      console.log(`  ❌ 事务回滚: ${error.message}`);
      return { success: false, error: error.message };
    }
  }

  // 定时任务：扫描未发送的消息并发送
  scanAndSendMessages(sendFunction) {
    const pendingMessages = this.messageTable.filter(m => m.status === 'pending');

    if (pendingMessages.length === 0) return;

    console.log(`\n[${this.serviceName}] 扫描到 ${pendingMessages.length} 条待发送消息`);

    for (const message of pendingMessages) {
      try {
        sendFunction(message);
        message.status = 'sent';
        message.updatedAt = Date.now();
        console.log(`  ✅ 消息 ${message.id} 已发送`);
      } catch (error) {
        message.retryCount++;
        message.updatedAt = Date.now();
        if (message.retryCount >= message.maxRetries) {
          message.status = 'failed';
          console.log(`  ❌ 消息 ${message.id} 发送失败（已达最大重试次数）`);
        } else {
          console.log(`  ⚠️ 消息 ${message.id} 发送失败，第 ${message.retryCount} 次重试`);
        }
      }
    }
  }

  // 下游服务：接收消息并幂等处理
  receiveMessage(message, handler) {
    // 幂等检查
    if (this.processedMessages.has(message.id)) {
      console.log(`[${this.serviceName}] 消息 ${message.id} 已处理过，跳过`);
      return { processed: false, reason: 'duplicate' };
    }

    try {
      handler(message, this.businessData);
      this.processedMessages.add(message.id);
      console.log(`[${this.serviceName}] ✅ 消息 ${message.id} 处理成功`);
      return { processed: true };
    } catch (error) {
      console.log(`[${this.serviceName}] ❌ 消息 ${message.id} 处理失败: ${error.message}`);
      return { processed: false, error: error.message };
    }
  }

  getMessageStatus() {
    return this.messageTable.map(m => ({
      id: m.id,
      topic: m.topic,
      status: m.status,
      retryCount: m.retryCount,
    }));
  }
}

// ========== 使用示例 ==========

// 订单服务
const orderService = new LocalMessageTable('订单服务');

// 库存服务
const inventoryService = new LocalMessageTable('库存服务');

// 1. 订单服务创建订单并写入本地消息
orderService.executeWithMessage(
  (data) => {
    data.set('order-001', { status: 'created', amount: 299, product: 'PROD-001', quantity: 2 });
  },
  {
    id: 'msg-order-001',
    topic: 'order-created',
    body: { orderId: 'order-001', product: 'PROD-001', quantity: 2 },
  },
);

// 2. 定时任务扫描并发送消息
orderService.scanAndSendMessages((message) => {
  // 模拟发送到消息队列
  console.log(`  → 发送到 MQ: ${message.topic}`);

  // 下游服务消费消息
  inventoryService.receiveMessage(message, (msg, data) => {
    const currentStock = data.get(msg.body.product) || { stock: 100 };
    currentStock.stock -= msg.body.quantity;
    data.set(msg.body.product, currentStock);
    console.log(`  库存扣减: ${msg.body.product} -${msg.body.quantity}，剩余 ${currentStock.stock}`);
  });
});

// 3. 重复消费测试（幂等）
console.log('\n--- 重复消费测试 ---');
inventoryService.receiveMessage(
  { id: 'msg-order-001', body: { orderId: 'order-001', product: 'PROD-001', quantity: 2 } },
  () => {},
);

console.log('\n消息状态:', orderService.getMessageStatus());
```

## 📢 最大努力通知

最大努力通知是最弱的一致性保证，适用于**对一致性要求不高**的跨系统通知场景：

```js
// ========== 最大努力通知 ==========

class BestEffortNotifier {
  constructor() {
    this.notificationLog = [];
    this.retryIntervals = [1000, 5000, 30000, 120000, 600000]; // 递增的重试间隔
  }

  // 发送通知（带递增重试）
  notify(target, payload) {
    const notification = {
      id: `notify-${Date.now()}`,
      target,
      payload,
      attempts: 0,
      maxAttempts: this.retryIntervals.length,
      status: 'pending',
    };

    console.log(`[通知] 发送到 ${target}: ${JSON.stringify(payload)}`);

    // 模拟多次重试
    for (let i = 0; i < notification.maxAttempts; i++) {
      notification.attempts++;
      const success = this.attemptSend(target, payload, i);

      if (success) {
        notification.status = 'delivered';
        console.log(`  ✅ 第 ${notification.attempts} 次发送成功`);
        this.notificationLog.push(notification);
        return { success: true, attempts: notification.attempts };
      }

      const nextInterval = this.retryIntervals[i];
      console.log(`  ⚠️ 第 ${notification.attempts} 次发送失败，${nextInterval}ms 后重试`);
    }

    notification.status = 'failed';
    this.notificationLog.push(notification);
    console.log(`  ❌ 达到最大重试次数，放弃通知`);
    console.log(`  → 提供查询接口供对方主动查询`);
    return { success: false, attempts: notification.attempts };
  }

  // 模拟发送（随机成功/失败）
  attemptSend(target, payload, attemptIndex) {
    // 模拟：前两次失败，第三次成功
    return attemptIndex >= 2;
  }

  // 提供查询接口（被通知方主动查询）
  queryResult(notificationId) {
    const notification = this.notificationLog.find(n => n.id === notificationId);
    if (!notification) return null;
    return {
      id: notification.id,
      status: notification.status,
      payload: notification.payload,
    };
  }
}

// 使用场景：支付结果通知商户
const notifier = new BestEffortNotifier();
notifier.notify('https://merchant.example.com/callback', {
  orderId: 'ORD-6001',
  paymentStatus: 'success',
  amount: 199,
});
```

## 📊 分布式事务方案对比

| 方案 | 一致性 | 性能 | 侵入性 | 适用场景 |
|------|--------|------|--------|---------|
| **2PC** | 强一致 | 低 | 低 | 数据库层面（XA 事务） |
| **3PC** | 强一致 | 低 | 低 | 理论改进，工程少用 |
| **TCC** | 最终一致 | 高 | 高 | 资金类业务（转账、支付） |
| **Saga** | 最终一致 | 高 | 中 | 长事务、跨多服务编排 |
| **本地消息表** | 最终一致 | 高 | 中 | 异步确保型（订单→库存） |
| **最大努力通知** | 弱一致 | 最高 | 低 | 跨系统通知（支付回调） |
