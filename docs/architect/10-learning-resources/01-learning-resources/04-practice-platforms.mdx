## 📖 概述

架构师的能力不是"看出来的"，是"做出来的"。读了 10 本书、订阅了 20 个博客，真正形成判断力的方式还是**动手**：做系统设计、读大型开源项目源码、在云上亲自搭建一次。本文讲清三类实战路径——**系统设计练习、开源项目精读、云平台实验**——并给出每类的可执行方法。

## 🧩 系统设计练习

### 为什么练系统设计

- **训练架构直觉**：面对模糊需求快速提取关键约束
- **练习权衡思维**：在可用性/一致性/成本/延迟之间做选择
- **提升沟通能力**：用图 + 语言清晰表达设计意图
- **面试必考**：大厂架构岗几乎必考

### 经典题目（值得反复练）

| 题目 | 核心考点 |
|------|---------|
| **设计短链接服务** | ID 生成、缓存、持久化、跳转性能 |
| **设计分布式限流** | 令牌桶、滑动窗口、Redis / 本地组合 |
| **设计分布式 ID 生成器** | Snowflake、时钟回拨、跨数据中心 |
| **设计秒杀系统** | 限流、排队、库存扣减、容灾 |
| **设计即时通讯系统** | 长连接、在线状态、推送、离线消息 |
| **设计 Feed 流（朋友圈/微博）** | 推拉模型、大 V 问题、时序存储 |
| **设计搜索引擎** | 倒排索引、分片、排序、召回 |
| **设计推荐系统** | 召回-排序、特征、在线/离线 |
| **设计支付系统** | 一致性、对账、幂等、安全 |
| **设计 Uber/外卖派单** | 地理位置、实时匹配、调度 |
| **设计日志/监控系统** | 采集、聚合、存储、查询 |
| **设计分布式文件系统** | Chunk、副本、元数据、一致性 |
| **设计视频点播/直播** | CDN、转码、流媒体、互动 |
| **设计云盘** | 上传、去重、分块、秒传 |
| **设计协同编辑（如 Google Docs）** | OT / CRDT、冲突解决 |

### 系统设计五步法

无论什么题目，都用统一的五步框架：

```
Step 1  澄清需求（5 min）
  - 功能需求：核心功能、非核心功能
  - 非功能需求：QPS、延迟、数据量、一致性要求
  - 明确规模：DAU、请求量级、数据量级

Step 2  容量估算（5 min）
  - 读写 QPS
  - 存储量（每天/总量）
  - 带宽
  - 服务器数量数量级

Step 3  高层设计（10~15 min）
  - 核心组件：客户端、网关、服务、存储
  - 数据流图
  - API 设计

Step 4  深入细节（15~20 min）
  - 每个关键组件的内部设计
  - 数据库表结构、缓存策略
  - 扩展性：分片、副本、负载均衡

Step 5  权衡与扩展（5~10 min）
  - 单点问题
  - 一致性权衡
  - 成本与收益
  - 演进路径：1x → 10x → 100x 怎么演进
```

### 练习节奏建议

- **第一阶段（1~2 个月）**：用五步法做完 10 道经典题，每题 60 分钟
- **第二阶段（2~4 个月）**：挑 3~5 道题做深度版，每题写 2000 字设计文档 + 架构图
- **第三阶段（持续）**：每月做 1 道前沿题（如"设计一个 LLM 服务平台"）

## 🔬 开源项目精读

### 为什么要精读源码

- 书和博客讲的是**抽象模式**，源码讲的是**工程落地的所有细节**
- 一流项目的架构、测试、文档体系是最好的活教材
- 精读 1 个大项目，胜过泛看 10 个

### 推荐项目路线

### 源码精读方法：4W + 3 层

**先问 4 个 W：**

- **Why**：这个项目解决什么问题？
- **What**：核心能力有哪些？对标的竞品是谁？
- **Who**：主要作者、社区规模、核心贡献者背景
- **When**：项目的关键演进节点、版本里程碑

**再做 3 层阅读：**

```
Layer 1  顶层架构（1~3 天）
  - 官方文档的 Architecture 章节
  - README、Design Docs、KEP / RFC
  - 顶层模块划分、主要依赖、部署拓扑
  - 产出：一张手绘的"项目架构全景图"

Layer 2  主流程（1~2 周）
  - 选 1~2 条核心链路（如 Kafka 的"消息生产-落盘-消费"）
  - 从入口函数追到存储层，画时序图
  - 关注：并发模型、错误处理、扩展点
  - 产出：主流程时序图 + 关键代码注释

Layer 3  专题深挖（持续）
  - 挑 1~2 个专题做极致深挖（如 Raft 实现、MVCC、调度器）
  - 读对应论文/设计文档 + 实现 + 测试
  - 尝试复现或改进
  - 产出：专题技术文章、Patch/PR
```

### 精读工作法

- **带着问题读**：如"Kafka 如何做到高吞吐？" 比"读完 Kafka" 具体得多
- **读测试用例**：测试是理解行为最准确的文档
- **跟踪 PR**：观察 Issue → 讨论 → PR → Merge 的过程，学习社区治理
- **定期 Commit 历史考古**：`git log -p <file>` 能看到一个模块的演进脉络
- **借助工具**：IDE 的"Call Hierarchy"、Sourcegraph、AI 代码库问答（Cursor、Aone Copilot）显著加速

### 阅读节奏建议

- 每年选 1~2 个项目做深度精读（L2+L3）
- 每季度泛读 1 个新项目（仅 L1）
- 持续跟进已精读项目的 Release Notes、重要 RFC

### 把源码精读转化为个人资产

- **写系列博客**：每深入一个模块，输出一篇文章
- **社区贡献**：从 Good First Issue 入手，逐步贡献代码
- **内部分享**：把精读内容在团队内做分享
- **技术演讲**：在 Meetup / 行业会议上分享自己的精读成果

## 🏆 架构 Kata 与内部训练

### 什么是架构 Kata

Architecture Kata 是 Ted Neward 推广的架构训练形式：**给出一个模糊需求，限时（通常 60~90 分钟）产出架构方案，然后公开评审**。非常适合团队内训。

### 团队训练方法

```
Step 1  出题（10 min）
  - 1 个真实或虚拟的业务场景
  - 明确约束：时间、规模、合规

Step 2  独立设计（30~45 min）
  - 个人 / 小组独立完成
  - 产出：1 页架构图 + 关键决策列表

Step 3  互相评审（30 min）
  - 小组间互相挑战
  - 围绕权衡与风险讨论

Step 4  讲师总结（15 min）
  - 点评各方案的亮点与盲区
  - 回归到架构原则
```

推荐资源：
- [Ted Neward's Architecture Katas](https://www.architecturalkatas.com/)
- 《软件架构：架构模式、特征及实践指南》配套 Kata 题目

## 📦 沉淀实战成果

所有实战如果不沉淀，半年后全忘。建议建立个人知识资产库：

```
个人技术资产库
  │
  ├─ 系统设计案例集
  │   ├─ 每题一份 Markdown + 架构图
  │   └─ 按主题分类（限流、ID 生成、IM 等）
  │
  ├─ 源码精读笔记
  │   ├─ 每项目一个 Repo
  │   └─ 主流程时序图、专题文章、思考
  │
  ├─ 云实验手册
  │   └─ 每个实验一份可复现步骤
  │
  └─ 个人项目仓库
      └─ 每个项目完整 README + 架构说明
```

存储方式：GitHub / 个人博客 / Notion / Obsidian，选一个长期坚持最重要。
